### 2026-08-11 · 배포 산출물을 둘로 나누지 않는다

**로컬화를 하는 이유부터** — 학교망은 CDN을 막는 경우가 많다. 배포되는 사이트 자체가
로컬화된 번들이어야 **CDN을 막는 학교망에서도 수업이 된다.** 오프라인 zip은 덤이 아니라
같은 목적의 다른 배달 방법이다.

예전에는 Pages용(CDN 유지)과 릴리즈 zip용(로컬화)을 따로 만들었다.
**zip은 아무도 열어 보지 않아 결함이 그쪽에만 쌓였다.**

실제로 `프로그래밍(Python)/1-1-2`에서 런타임에 조립된 클래스 8개 중 **3개가 zip에서만 빠진 채**
오래 남아 있었다. 소스를 그대로 열면 CDN 런타임 JIT라 멀쩡히 보이므로 눈으로는 잡히지 않았다.

같은 파일을 서빙하면 **사이트를 보는 사람이 곧 번들의 검증자가 된다.**
2026-08-11에 하나로 합쳤다.

**그래도 「같은 파일」이 「같게 동작한다」는 뜻은 아니었다.** 합친 뒤에도 zip에서만
깨지는 것이 남아 있었다 — `<script type="module">`이다. 모듈은 CORS를 타는데
`file://`의 출처는 `null`이라 브라우저가 무조건 거절한다. 라이브러리가 실리지 못해
시뮬레이터의 그래프·트리·차트가 통째로 안 그려졌는데, **사이트에서는 멀쩡했다.**
2026-08-19에 빌드가 평범한 스크립트로 눌러 담게 고치고, 모듈이 다시 새어 나가면
`check -- dist`가 CI를 세우게 했다. **배달 방법이 둘이면 검사도 둘 다를 봐야 한다.**

### 2026-08-11 · CDN에서 npm + Vite로 — 밟은 함정

2026-08-11에 소스 HTML의 CDN을 전부 걷어냈다. 옮기는 것 자체보다 **옮긴 뒤에
조용히 깨지는 것**을 찾는 데 시간이 들었다.

| 함정 | 어떻게 드러났나 |
|---|---|
| **npm 판과 CDN 판의 API가 다르다** | lucide UMD는 `createIcons()`만으로 됐지만 npm 판은 아이콘 목록을 받는다. 콘솔 오류가 나서 바로 잡혔다 |
| **최상위 `await`는 `window.onload`보다 늦다** | Prism 언어 확장을 동적 import로 붙였더니 하이라이팅이 **조용히** 실패했다. 오류도 없고 토큰만 0이었다 |
| **전역에 얹는 순서가 있다** | Prism 언어 확장은 전역 `Prism`이 선 뒤에 평가되어야 한다. 진입점에서 `_lib/prism.js`를 먼저 `import` 하는 정적 순서로 맞췄다 |
| **모듈은 defer라 인라인 스크립트보다 늦다** | 인라인에서 라이브러리를 바로 부르는 파일을 찾아야 했다. **들여쓰기로 세면 48개, 괄호 깊이로 세면 1개** — 앞의 것은 `window.onload` 안까지 센 과대추정이었다 |
| **버전을 안 맞추면 조용히 깨진다** | npm 기본이 Font Awesome 7(아이콘 이름 변경), p5 2.x(호환 깨짐)였다. **소스가 쓰던 CDN 주소의 버전으로 못박았다** |

**되는지는 브라우저로만 확인된다.** 클래스 대조와 링크 검사는 전부 통과했는데도
하이라이팅이 죽어 있었다. 라이브러리를 옮겼으면 대표 페이지를 실제로 띄워 본다.

**클래스를 코드로 조립하지 않는 까닭** — 빌드는 리터럴로 있는 클래스만 굽는다. `bg-${x}-50`은
CSS에서 빠지는데 dev에서는 멀쩡히 보인다. **JS 문자열에 적은 Tailwind 클래스도 같다**(2026-09-25
사용자 확정). Tailwind는 HTML만 읽고 `src/entries/`의 JS는 읽지 않아, JS에 적은 클래스는 같은 것이
우연히 HTML에 있을 때만 살았다 — CDN 시절 런타임이 다 구워 주던 흔적이다. 그래서 JS에는 뜻을 가진
이름만 적고 모양은 CSS에서 `@apply`로 준다. `check -- classes`가 Tailwind에게 직접 구워 보게 해서 잡는다.

### 2026-09-25 · 명령은 한 곳에서 정의한다

CI도 IDE 실행 구성도 `npm run` 이름만 부르므로 `package.json`(검사·감사는 `tools/run.mjs`)
한 곳만 고치면 셋이 함께 바뀐다. 로컬과 CI가 같은 한 줄 `npm run ci`를 돌므로 로컬에서 초록이면
CI도 초록이다. 터미널에서 부르면 특정 편집기에 매이지 않는다.

- **헷갈리는 이름** — `sim`과 `sims`가 나란히 있던 적이 있다.
- **파이썬 검사를 들이지 않는 까닭** — 2026-09-25 사용자 지시로 검사를 전부 Node/Vitest로 옮겼다.
- **fixtures를 함께 넣는 까닭** — 저장소가 깨끗하면 「위반 0」은 검사가 망가졌을 때도 똑같이 나온다.
- **돌연변이를 더하는 까닭**(2026-09-25 사용자 지시) — 오류를 못 잡으면서 초록인 검사는 없는 것보다
  나쁘다. 첫 전수 돌연변이에서 넷이 살아남았다 — 경사 하강 학습기 · 설명문의 개수 · CSS의 `fs-on`은
  아무 검사도 보고 있지 않았다. 오래 걸려 `ci` 밖에 둔다.

### 2026-08-27 · 문서와 주석이 낡는 까닭

산문은 고쳐도 CI가 보지 않으므로 **조용히 거짓이 된다.**

- 「위반 0건」·「146개를 굽는다」는 적는 순간 썩기 시작한다. 결과는 도구가 출력할 자리다.
- 「소스에 CDN이 없다」고 적으면 낡지만, 「`check -- dist`가 CDN 잔존 0을 보증한다」고 적으면
  낡을 수가 없다 — 보증이 바뀌면 CI가 빨간불이 되기 때문이다.
- 날짜가 있으면 독자가 「틀린 말」이 아니라 **「옛날 말」**로 읽고 알아서 할인한다.
- 줄 번호 · 형제의 개수 · 차례는 한 줄만 끼워 넣어도 전부 어긋나는데 **어긋난 것을 아무도 알려
  주지 않는다**(2026-08-27 사용자 확정). 이름은 바꾸면 코드가 먼저 깨지므로 고치지 않고는 지나갈 수 없다.
- 도구 사용법을 README와 머리 주석 두 군데에 적으면 **반드시 갈라진다**(2026-09-26 사용자 확정).
  정리해 보니 README가 코드와 이미 어긋난 곳이 둘 있었다.

### 2026-09-27 · 까닭이 적히지 않았던 저장소 규칙의 까닭을 사용자가 밝힘

문서 구조를 정리하며 판례에 까닭이 없는 규칙을 모아 물었고, 사용자가 이렇게 답했다.

- **빌드 설정을 `vite.config.js` 하나에 둔다** — 설정 파일이 둘 이상이면 반드시 갈라지거나 헷갈린다.
- **커밋 메시지에 AI 협업 표시를 쓰지 않는다** — 코드 소유자의 결정이다.
- **`master`에 직접 커밋한다** — 이 저장소는 주로 혼자 작업하고, `master`에 푸시하는 것이 곧 배포가 아니다(배포는 손으로 누른다).
  브랜치를 두면 관리만 복잡해진다.
- **`index.html` 등록은 사용자가 지시할 때만 한다** — 미완성인 강의노트나 과목이 목록에 올라 배포되지 않게 하려는 것이다.
- **강의노트의 점검 · 확인은 중단원 단위로 묶는다** — 소단원 하나씩 하는 것보다 효율적이다. 전에는 「「정보」는 중단원」으로
  적혀 있었는데, 과목에 딸린 규칙이 아니라 점검 단위의 문제라서 과목과 상관없이 중단원으로 고쳤다.
- **태그의 메이저 번호** — 사용자가 이날 문서 구조 정리를 마치고 5.0.0으로 올렸다. 메이저를 올리는 것은 사용자가 정한다.

### 2026-09-29 · 페이지 <style>을 공용 틀로 옮기며 밟은 것들

다크 모드(결정.md D-041)를 들이며, 과목마다 페이지 <style>에 복제돼 있던 틀을 공용 CSS로 옮겼다. 네 과목은 과목 안에서
틀이 한 글자도 다르지 않아 `_note.css` 한 벌이 되었고, 인공지능기초 · AI 시뮬레이터는 편마다 달라 이름 클래스와 편별 파일로 옮겼다.
**라이트 화면을 그대로 둔다는 증거**가 먼저 있어야 해서 `audit -- styles`(계산된 스타일을 떠 두고 견주는 도구)를 먼저 만들었다.
옮기면서 계단식 순서가 몇 번이나 뒤집혔고, 모두 스냅샷이 먼저 알려 주었다.

- **틀은 유틸리티보다 뒤라야 한다.** 페이지 <style>은 링크된 CSS보다 뒤에 있어 같은 특정도의 유틸리티를 이겼다
  (`th, td`의 여백이 `<th class="p-3">`을 이기는 식). 그래서 `_tailwind.css`를 떼어 두고 진입 CSS가 그 뒤에 틀을 가져온다.
- **`@tailwind variants`를 적어야 한다.** 적지 않으면 Tailwind는 `md:` · `hover:` 변형을 스타일시트 맨 끝에 붙인다.
  옛 <style>은 그보다도 뒤였으므로 `md:p-8`을 이겼는데, 옮긴 틀은 변형보다 앞에 놓여 졌다(AI 시뮬레이터 카드 여백).
  1366px 스냅샷에는 드러나지 않는 승부가 많아 375px 기준선을 HEAD의 worktree에서 따로 떴다.
- **범위를 걸 때는 `:where()`로 건다.** `.sim-bfs .grid-cell`처럼 클래스를 하나 더 붙이면 특정도가 올라 hover 유틸리티와의 승부가
  뒤집힌다 — 스냅샷이 재지 못하는 곳이다. `:where(.sim-bfs) .grid-cell`은 원래와 특정도가 같다.
- **범위를 걸 수 없는 규칙이 새어 나간다.** 스크롤 막대(`::-webkit-scrollbar`)를 범위 없이 옮겼더니 같은 CSS를 쓰는 CS 시뮬레이터의
  막대 폭이 바뀌어 칸 폭이 7px씩 달라졌다. `html:has(> body.sim-ai)`와 `:where(.sim-ai) ::-webkit-scrollbar`로 좁혔다.
- **공통 틀이 기대던 것을 모르고 씌우면 단서가 사라진다.** `details > summary { list-style: none }`은 쉐브론 아이콘을 직접 넣은 과목에서만
  맞다. 인공지능기초는 브라우저의 ▶에 기대고 있어, 쉐브론이 있을 때만(`:has(.details-chevron)`) 숨기게 고쳤다.
- **옮기다 잠자던 버그가 드러났다.** 인공지능기초 1-2-3의 <style>에 잘못 들어간 글자 하나가 다음 선택자에 붙어 그 편의 퀴즈 틀이
  아예 걸리지 않고 있었다. 2-1-5의 `.code-block` 규칙은 쓰는 요소가 없는 죽은 코드였는데, 빌드가 코드 블록에 씌우는 래퍼와 이름이 같아
  과목 CSS로 올렸다면 모든 편의 코드 블록을 망가뜨렸을 것이다.
- **지키는 검사** — `check -- colors`(페이지 HTML에 색을 박지 않는다), `check -- dark`(다크의 대비 · 밝은 칸 · 섬),
  `audit -- styles save|diff --width=…`(옮기기 전후 견주기, ci 밖).

### 2026-09-30 · 인라인 style을 클래스로 옮기며 밟은 것들

다크를 들이며 <style>은 모두 공용 틀로 옮겼지만 마크업의 `style=""` 1,140개(글머리 점 783 · SVG 폭 232 · 히트맵 칸 · 막대 높이 …)와
강의노트 퀴즈 토스트가 스크립트로 박는 스타일(171편)이 남아 있었다. 사용자가 「다크를 지원한다는 것은 CSS를 표준 관행대로 응집한다는 것 —
인라인 대신 클래스」라고 정해, 되풀이되는 모양은 뜻 이름(`.bullet-dot` · `.quiz-toast` · `.code-frame`)으로, 자료인 크기 · 위치는
임의값 클래스(`h-[13%]` · `min-w-[576px]`)로 옮겼다. 라이트 1366 · 375, 다크 1366 스냅샷으로 견주었다.

- **인라인은 늘 이겼지만 클래스는 틀에 진다.** 틀(`_note.css` · 과목 CSS)은 유틸리티보다 뒤에 온다. 인공지능기초 1-1-2의
  `<table class="table-prose" style="min-width:540px">`를 `min-w-[540px]`로 옮기면 `table.table-prose{min-width:32rem}`에 져서 512px가 된다.
  `!`를 붙이지 않고 틀 바로 아래 수식어(`table.table-prose.table-roomy`)로 두었다.
- **검사 도구가 인라인만 읽고 있었다.** `check -- html`의 SVG 글자 환산은 `max-width`를, `audit -- svg`는 「높이 고정 조상」을 인라인에서만 읽었다.
  옮기기 전에 둘이 클래스도 읽게 고치고, 두 도구의 출력이 옮긴 뒤에도 같은지 보았다.
- **죽은 요소가 숨어 있었다.** 강 건너기의 배 위 농부 · 짐 칸 넷은 스크립트가 늘 숨기기만 했다. `hidden`으로 바꾸면 `.farmer-token{display:flex}`
  (틀)이 이겨 나타났을 것이다 — 지웠다.
- **옛 `colors` 검사의 섬 판정이 틀려 있었다.** 섬을 `keep:table`로 쌓아 `</table>`에서 못 빼, 섬 뒤의 요소를 모두 섬 안으로 보았다.
- **섬이 바탕을 갖지 않았다.** 데이터과학 2-3-1 히트맵(`data-keep-color`)의 홀수 줄 · 머리 칸이 투명해, 다크에서 짙은 카드가 비치고
  섬이 지킨 짙은 글자가 사라졌다. 라이트에서는 흰 카드라 안 보인다. `check -- dark`는 색이 바뀌었는지만 보았으므로 놓쳤다.
- **다크 스냅샷의 잡음** — 필터가 걸린 SVG의 `margin: auto` 계산값이 0 ↔ 수백 px로 흔들린다. 상자(자리 · 크기)는 그대로다.
- **지키는 검사** — `check -- inline-css`(<style> · `style=""` · 섬 밖 임의 색 · 강의노트 스크립트의 style 쓰기),
  `check -- dark`(섬 안 글자의 바탕이 섬 밖에서 오면 건다), `check -- html`(`max-w-[…]`를 천장으로 읽는다).

### 2026-10-22 · 검사 워크플로를 병렬 잡으로 가름

푸시마다 도는 검사가 한 잡에서 `npm run ci` 한 줄을 돌고 있었다. 벽시계가 모든 조각의 합이라, 검사를 더할수록 푸시한 뒤 기다리는
시간이 그만큼 길어진다. 조각은 서로 기다릴 까닭이 없다 — 시뮬레이터 동작 검사는 브라우저 검사의 결과를 쓰지 않는다.
그래서 **사람이 치는 입구는 `npm run ci` 한 줄로 두고, 액션에서만 그 조각을 잡 여럿에 흩었다**(`ci:full` 같은 두 번째 실행점을
만들지 않는다 — D-019는 그대로다).

- **묶음을 워크플로에 적지 않았다.** 이름을 YAML에 늘어놓으면 새 검사를 더할 때마다 두 곳을 고쳐야 하고, 한쪽을 잊으면
  그 검사는 러너에서 영영 돌지 않는다. `tools/run.mjs`의 `ciJobs()`가 규칙으로 가르고(정적 검사 · 브라우저 검사 하나씩 ·
  무거운 시뮬레이터 검사 하나씩 · 나머지 시뮬레이터 검사를 `SIM_SHARDS`개로), `npm run plan`이 그것을 매트릭스 JSON으로
  찍어 준다. 워크플로는 받아 쓸 뿐이라 검사를 더해도 고칠 것이 없다.
- **처음 가른 모양이 기울어 있었다.** 시뮬레이터 검사를 그냥 돌려 가며 나눴더니 한 묶음이 다른 묶음의 여섯 배였다.
  하나씩 재어 보니 `dark`와 `sim nqueen`이 홀로 다른 묶음 전체보다 오래 걸렸다(2026-10-22에 이 컴퓨터에서 잼).
  **파일 하나는 더 나뉘지 않으므로 가장 무거운 검사 하나가 벽시계의 바닥이다** — 그 둘을 각자 잡으로 떼고 나머지를 그 밑으로 맞췄다.
  무거운 것의 목록(`SIM_HEAVY`)은 고르게 나누기 위한 눈금일 뿐이라 낡아도 러너는 같은 것을 다 돌고 벽시계만 나빠진다.
  이름을 잘못 적으면 조용히 기우므로 `check -- ci-plan`이 그 이름이 실제로 도는 검사인지 본다.
- **나누면 조용히 빠진다.** 빠진 조각은 아무도 빨간불을 켜 주지 않으므로 「러너가 초록이다」가 뜻을 잃는다. `check -- ci-plan`이
  묶음과 전부 돌리기를 **같은 함수(`filesFor`)로 테스트 파일 목록까지 풀어** 맞대고, 워크플로가 그 묶음 · 빌드 · 산출물 검사를 실제로 부르는지 본다.
- **끊기 설정이 형제 잡을 끊는다.** `concurrency`를 잡에 그대로 두면 같은 이름을 받은 잡들이 서로를 끊는다. 워크플로 차원으로 올렸다.
- **이름에는 있고 돌지는 않는 꼴.** 처음에는 워크플로 파일 전체를 글자로 뒤져 `npm run check -- dist`를 찾았더니, 단계 이름(`name:`)에
  적힌 같은 글에 걸려 돌연변이가 살아남았다. 도는 줄(`run:`)만 보게 고쳤다.
- **브라우저는 필요한 잡에서만 깐다.** Chromium 설치가 짧지 않다 — 정적 검사 잡이 그것을 기다릴 까닭이 없다.
- **설치가 감사를 기다리고 있었다.** 잡이 여럿이 되어 `npm ci`도 그만큼 돈다. 검사의 판정은 취약점 감사 결과와 상관없고
  의존성 경보는 Dependabot이 따로 맡으므로, 두 워크플로의 설치 세 자리에 `--no-audit`를 붙였다(사용자가 정함).
  `check -- ci-plan`이 배포 워크플로까지 보고 지킨다.
