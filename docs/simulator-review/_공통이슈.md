# AI 시뮬레이터 공통 이슈 누적

검증 기준: 고등학교 「인공지능 기초」 / 루브릭 4축(A 개념 정확성 · B 시각화 정합성 · C 안정성 · D 접근성·반응형)

> 제외 합의 사항: 형성평가(퀴즈) 부재는 감점하지 않음. CDN 전면 의존은 학교 온라인 환경 기준 **의도된 설계**이므로 감점하지 않음.

## 반복 확인된 패턴

### 1. 터치/포인터 이벤트 미지원 (접근성)
- **해당**: search-bfs-dfs (✅ 수정 완료)
- 격자·캔버스 조작을 `mousedown` / `mouseenter` 로만 바인딩. 태블릿에서 드래그 조작 불가(단일 탭만 동작).
- **표준 수정 레시피** (이후 파일에도 그대로 적용):
  ```javascript
  cell.addEventListener('pointerdown', onDown);
  cell.addEventListener('pointerenter', onEnter);
  document.onpointerup = document.onpointercancel = () => isDrawing = false;

  function onDown(e) {
      // 터치는 첫 요소에 포인터가 암묵 캡처되어 이웃의 pointerenter가 안 뜬다 → 반드시 해제
      if (e.pointerId !== undefined && e.currentTarget.hasPointerCapture?.(e.pointerId)) {
          e.currentTarget.releasePointerCapture(e.pointerId);
      }
      ...
  }
  ```
  컨테이너에 `touch-action: none;` 을 함께 지정해 드래그 중 페이지 스크롤을 막을 것.

### 2. 모바일 터치 타깃 44px 미달
- **해당**: search-bfs-dfs (375px에서 격자 셀 28×28px)

### 3. 키보드 접근 / ARIA 부재
- **해당**: search-bfs-dfs (격자 셀이 `div`, tabindex·aria-label 없음)

### 4. 색상 단독 상태 구분
- **해당**: search-bfs-dfs (발견/방문/경로를 색으로만 구분, 경로만 아이콘 병기)

### 5. status 요소 자체가 flex 컨테이너 → innerHTML 문장이 토막남
- **해당**: search-heuristic (✅ 수정 완료)
- `innerHTML`로 `<b>` 등이 섞인 문장을 넣는 요소에 `flex`를 주면 텍스트 노드와 태그가
  **각각 별도 flex 아이템**이 되어 따로따로 줄바꿈된다.
- **레시피**: 바깥 div는 정렬용(`flex items-center justify-center`)으로만 두고, 메시지는
  안쪽 `<span>`에 넣어 그 span을 `getElementById` 대상으로 삼는다. 고정 높이(`h-14`)는
  `min-h-14`로 바꿔 여러 줄일 때 잘리지 않게 한다.
- **이후 파일 확인 포인트**: `setStatus`/`innerHTML` 대상 요소의 클래스에 `flex`가 있는지.

### 6. 교육 메시지가 알고리즘과 무관하게 고정
- **해당**: search-heuristic (✅ 수정 완료 — 그리디에도 "최적 경로"라고 표시하고 있었음)
- **확인 포인트**: 최적성·수렴·정확도를 단정하는 문구가 알고리즘/설정에 따라 달라져야 하는데
  하드코딩되어 있지 않은지. 시뮬레이터가 가르치려는 대비를 스스로 무너뜨리는 유형의 버그다.

### 7. 개념적 의미가 있는 값에 난수 사용
- **해당**: search-heuristic (✅ 수정 완료 — 트리 h가 1~20 난수였음)
- **확인 포인트**: 거리 추정·가중치·확률처럼 의미가 있는 값에 난수를 쓰면 핵심 직관이
  화면에서 사라지고 이론적 보장(예: A*의 admissible 조건)이 깨진다.

### 8. 우선순위 큐를 삽입할 때마다 전체 정렬 → 화면 정지
- **해당**: search-8-puzzle (✅ 수정 완료 — 최난도 상태에서 2.5초 정지)
- `elements.push(); elements.sort()` 패턴은 삽입이 수만 회에 이르면 O(N² log N)이 되어
  브라우저가 수 초간 얼어붙는다. A*·다익스트라·최우선 탐색 계열에서 반복 등장할 수 있다.
- **레시피**: 부모-자식만 비교하는 이진 최소 힙(sift-up / sift-down)으로 교체.
  같은 상태를 더 짧은 경로로 다시 넣는 구조라면, 꺼낼 때
  `if (current.g > best.get(key)) continue;` 로 옛 항목을 건너뛴다.
- **확인 포인트**: 탐색 루프에 `await`가 없는데 주석에는 "멈춤 방지"라고 적힌 경우가 있다.
  주석을 믿지 말고 최악 입력(8-퍼즐이면 31수 상태)으로 실제 시간을 재 볼 것.

### 9. 고정 높이(`h-N`) 텍스트 상자 → 좁은 화면에서 내용이 잘림 ⚠️ 최다 발생
- **해당**: search-heuristic(`h-14`), search-n-queen(`h-10`), supervised-linear-regression(`h-5`)
  — 셋 다 ✅ 수정 완료. **검증한 6개 중 3개에서 나옴. 새 파일마다 먼저 확인할 것.**
- linear-regression은 예제 설명 4개가 **전부** 안 보이는 상태였다(상자 20px / 내용 48px).
- **빠른 점검법**: 375px에서 `[...document.querySelectorAll('[class*=" h-"],[class^="h-"]')]`
  중 텍스트를 담는 요소를 골라 `scrollHeight > clientHeight` 확인.
- 좁은 화면에서 메시지가 두 줄이 되면 **잘려서 안 보인다.** 특히 "탐색 성공" 같은 결과 메시지가
  잘리면 학습 흐름이 끊긴다.
- **레시피**: `h-N` → `min-h-N` + `py-1.5`, `text-sm md:text-base` → `text-base`,
  `leading-snug break-keep` 추가. 375px에서 실제 메시지를 넣어 `scrollHeight > clientHeight` 확인할 것.

### 10. 참고 — 긴 탐색은 제너레이터로 양보할 것
- **좋은 예**: search-n-queen (`function* dfsGenerator` — 매 단계 yield, 화면 안 멈춤)
- **나빴던 예**: search-8-puzzle (동기 while 루프, 최난도에서 2.5초 정지)
- 단계별 재생이 필요한 탐색 시뮬레이터는 제너레이터가 정답 구조다. 일시정지·단계 진행·속도 조절이
  전부 공짜로 따라온다.

### 11. 카드 패딩이 모바일에서 콘텐츠를 짓누름
- **해당**: wumpus-world (✅ 수정 완료 — 격자가 246px까지 쪼그라들었음)
- `main`의 `px-6`(24px)와 카드의 `padding: 2.5rem`(40px)가 겹치면 375px 화면에서
  **좌우로만 128px**을 잃는다. 격자·차트처럼 정사각형 비율이 있는 요소가 직격탄을 맞는다.
- **레시피**: 카드 패딩을 모바일 `1.25rem`, `@media (min-width: 640px)` 에서 `2.5rem`으로 분리.
- **확인 포인트**: 375px에서 격자/차트 컨테이너의 실제 픽셀 폭을 재 볼 것. 뷰포트의 70% 미만이면 의심.

### 12. 하드코딩된 초소형 글자 (`text-[0.5rem]` 등)
- **해당**: wumpus-world (✅ 수정 완료 — 좌표 라벨 8px)
- 판 크기에 따라 글자를 줄이는 로직에 하한이 없으면 8px까지 내려가 읽을 수 없게 된다.
- **확인 포인트**: `text-[...rem]` / `text-[...px]` 임의값 클래스를 grep 하고, 10px 미만이면 상향.
- **주의**: Tailwind CDN은 동적으로 삽입된 임의값 클래스를 MutationObserver로 뒤늦게 생성한다.
  `changeSize()` 직후 바로 `getComputedStyle`을 재면 아직 반영 전이라 상위 요소 크기가 잡힌다.
  측정은 한 템포 뒤에 할 것.

### 13. `sort(() => Math.random() - 0.5)` 편향 셔플
- **해당**: wumpus-world (✅ 수정 완료)
- 비교 함수 일관성 규약 위반이라 균등하게 섞이지 않는다. Fisher-Yates로 교체할 것.

## 🚩 사용자 판단이 필요한 미해결 항목

### 다항회귀 실습이 실제로는 다중선형회귀 (supervised-polynomial-regression)
- 파일명은 `polynomial`, 내용은 **다중선형회귀**(`w1·x1 + w2·x2 + b`). 페이지 안에는 "다항"이 없음.
- 그런데 `index.html:467`은 라벨을 **"다항 회귀"** 로 달고,
  `인공지능기초/2-3-1.기계학습의-개념과-활용.html:368`은 "제곱·세제곱 항을 추가하는 모델"이라
  설명한 뒤 이 파일로 **[모델 실습하기]** 를 연결한다.
- 학생이 읽은 개념과 실습이 다른 개념이 된다. 선택지:
  1. 링크·강의노트 표기를 "다중선형회귀"로 정정 (다항회귀 실습은 없음을 인정)
  2. 시뮬레이터에 x² 항 다항회귀 모드 추가 (기능 개발)
  3. 파일명 변경 — 링크가 깨지고 북마크 문제가 있어 비권장
- 강의 구성 판단 + 다른 파일 2개 수정이 필요해 자동 진행에서 제외함.
