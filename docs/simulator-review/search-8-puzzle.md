## A. 개념 정확성 — 상 (수정 없음)

### ✅ 셔플이 "항상 풀 수 있는" 상태만 만듦
8-퍼즐의 대표적 함정은 타일을 무작위로 배치하면 **약 절반이 풀 수 없는 상태**(역위수 홀짝성이
목표와 다름)라는 점입니다. 이 시뮬레이터는 현재 상태에서 **합법 이동만 20회** 수행해 섞으므로
항상 해가 존재합니다. 올바른 구현입니다.

### ✅ 맨해튼 거리가 admissible
`getManhattanDistance`가 빈칸(0)을 제외하고 계산합니다. 빈칸을 포함하면 과대평가가 되어
A*의 최적성이 깨질 수 있는데, `if (state[i] === 0) continue;` 로 정확히 처리했습니다.

### ✅ A*가 실제로 최적해를 냄
BFS(최단 거리 기준)와 대조 검증:

| 항목 | 결과 |
|---|---|
| 무작위 셔플 15회 — A* 해 길이 ≠ BFS 최적 | **0건** |
| 알려진 최난도 상태(`867254301`) | **31수** — 이론적 최적값과 일치 |

메시지의 "최단 경로를 찾았습니다" 표현이 사실과 맞습니다.
(2번 파일에서 그리디에도 "최적"이라 표시하던 것과 대조적)

### ✅ 오개념 섹션이 정확
> "인공지능은 퍼즐을 보면 직감적으로 한 번에 딱 정답을 알아내는 거 아닌가요?"
> → 직감은 없고, 탐색 트리를 뻗어 체계적으로 연산한다

고등학교 수준에서 정확하고 필요한 지적입니다.

## B. 시각화 정합성 — 상

- 해를 찾은 뒤 이동 순서를 번호 뱃지로 하나씩 쌓아 보여 주고, 400ms 간격으로 실제 타일이
  움직입니다. "탐색 결과 = 행동 순서"라는 연결이 잘 드러납니다.
- 개념 → 규칙 → 시뮬레이션 → 정리 → 오개념 순서로 섹션이 구성되어 학습 흐름이 자연스럽습니다.

## C. 안정성 — 하 → 상 (핵심 수정)

### 🔴 최난도 상태에서 브라우저가 2.5초간 완전히 멈춤

`PriorityQueue.enqueue`가 **삽입할 때마다 배열 전체를 정렬**하고 있었습니다.

```javascript
enqueue(element, priority) {
    this.elements.push({element, priority});
    // 8-퍼즐 수준에서는 삽입 후 정렬하는 방식(O(N log N))으로도 충분히 빠릅니다.
    this.elements.sort((a, b) => a.priority - b.priority);
}
```

주석은 "충분히 빠르다"고 하지만, 8-퍼즐 최난도 상태는 **삽입 약 3만 회 · 큐 최대 9,310개**가
필요합니다. 매번 전체 정렬하면 총 비용이 O(N² log N)로 폭발합니다.

또한 탐색 루프에는 `await`가 하나도 없습니다. 주석에 "브라우저 멈춤을 방지하고 빠른 성능을
보장하는 탐색 루프"라 적혀 있지만 실제로는 **완전 동기 루프**라, 그 시간 동안 화면이 얼어붙고
클릭도 받지 않습니다.

실측:

| 상태 | 해 길이 | 확장 노드 | 소요 시간 |
|---|---|---|---|
| 셔플 20회 (버튼 1번) | ~20수 | 588 | 4ms |
| 셔플 200회 (버튼 10번) | 28수 | 8,152 | 437ms |
| 최난도 `867254301` | 31수 | 20,451 | **2,467ms** |

셔플은 현재 상태에서 이어서 섞이므로, 학생이 셔플 버튼을 여러 번 누르면 실제로 도달합니다.

### 수정: 이진 최소 힙 + 오래된 항목 건너뛰기

부모-자식만 비교해 올리고 내리는 이진 힙으로 교체해 삽입·삭제를 O(log N)으로 만들고,
같은 상태를 더 짧은 경로로 다시 넣었을 때 큐에 남은 옛 항목은 건너뛰도록 했습니다.

| | 수정 전 | 수정 후 |
|---|---|---|
| 최난도 상태 소요 시간 | 2,467ms | **24ms** (약 100배) |
| 해 길이 | 31수 | 31수 (동일) |
| 확장 노드 | 20,451 | 8,086 |

검증: 힙 불변식 검사(무작위 2,000개 삽입 후 추출 순서 정확), BFS 대조 15회 불일치 0.

### 그 외
- 콘솔 에러 0건.
- 퀴즈 버튼의 `innerHTML` 백업/복원에 이미 중복 방지 가드(`if (!b.dataset.originalHtml)`)가
  들어가 있습니다. 문제없습니다.
