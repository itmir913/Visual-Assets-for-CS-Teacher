## A. 개념 정확성 — 상 (수정 없음)

### ✅ 브루트포스 구현과 대조해 불일치 0
독립적으로 작성한 참조 k-NN(유클리드 거리 → 정렬 → 상위 k → 다수결)과 대조:

| 시행 | 분류 불일치 | 동점 판정 불일치 |
|---|---|---|
| 200회 (k = 1~7 무작위, 3클래스) | **0** | **0** |
| 150회 (k = 홀수, 25점) | **0** | — |

### ✅ 동점 처리가 명시적이고 합리적
```javascript
this.isTie = tiedClasses.length > 1;
if (this.isTie) {
    let closestTiedNeighbor = this.kNeighbors.find(n => tiedClasses.includes(n.point.cls));
    finalClass = closestTiedNeighbor.point.cls;
}
```
동점이면 **가장 가까운 이웃의 클래스**로 결정합니다. 표준적인 타이브레이크이고,
`isTie` 플래그를 UI까지 전달합니다(아래 B 참조).

### ✅ k 슬라이더가 홀수만 (`step="2"`, 1~29)
2클래스에서 동점이 나지 않도록 홀수로 제한한 것은 올바른 설계입니다.
다만 **3클래스**에서는 홀수 k에서도 동점이 날 수 있고(예: k=3에 A1 B1 C1),
그 경우를 위 타이브레이크가 정확히 처리합니다.

## B. 시각화 정합성 — 상 (수정 없음)

### ✅ 동점을 숨기지 않음
```javascript
if (knn.isTie) resultText += ` (동점: 거리 우선)`;
```
결과 배지에 동점 사실과 해소 방법을 함께 표시합니다.
**시뮬레이터가 자기 판단 근거를 드러내는 좋은 사례입니다.**
(2번 파일이 그리디에도 "최적 경로"라고 단정하던 것과 대조적)

- 클래스별 투표수(A/B/C)를 실시간 카운터로 보여 줍니다.
- 거리 계산 → 이웃 선택 → 투표 단계가 분리되어 단계별로 관찰할 수 있습니다.

## C. 안정성 — 상 (수정 없음)

경계 케이스 전수 시험 — **예외 0건**:

| 케이스 | 결과 |
|---|---|
| 데이터 0개 | 예외 없음. 화면에 "대기 중" 표시 |
| k(7) > 데이터 수(2) | 이웃 2개로 자동 축소. 정상 분류 |
| k = 1 | 최근접 이웃 클래스 반환 |
| 완전 동점 (A 1표, B 1표) | 동점 판정 + 거리 우선 해소 |
| 질의점이 데이터점과 완전히 같음 | 거리 0, 정상 처리 |

- 캔버스 입력이 `addEventListener('click', …)`이라 터치에서도 정상 동작합니다.
  (드래그가 필요 없는 조작이라 `pointerdown` 전환이 불필요합니다.)
- 콘솔 에러 0건.

## 남긴 항목 (미수정)

- **k-NN의 특성 스케일 민감성**을 다루지 않습니다. 두 축의 단위가 크게 다르면 유클리드 거리가
  한 축에 지배되는데, 이는 k-NN의 대표적 주의점입니다. 다만 이 시뮬레이터는 두 축이 같은
  캔버스 좌표계라 문제가 드러나지 않으며, 고등학교 수준에서 필수는 아니라고 판단했습니다.
- k를 데이터 수보다 크게 잡으면 조용히 축소됩니다(예외는 없음). 안내 문구가 있으면 더 좋겠습니다.
