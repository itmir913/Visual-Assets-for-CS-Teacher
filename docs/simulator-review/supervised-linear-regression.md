## A. 개념 정확성 — 상 (수정 없음)

### ✅ 경사하강 미분식이 정확
```javascript
dw += (pred - p.y) * p.x;   dw = (2 / N) * dw;
db += (pred - p.y);         db = (2 / N) * db;
```
MSE = (1/N)Σ(ŷ−y)² 의 편미분과 정확히 일치합니다. 계수 2까지 살아 있습니다.

### ✅ 학습 결과가 최소제곱 닫힌 해와 일치
경사하강으로 수렴시킨 뒤 정규방정식 해와 대조했습니다.

| 데이터 | 학습 결과 (w, b) | 닫힌 해 (w, b) | 반복 | MSE 차 |
|---|---|---|---|---|
| 완전 직선 `y=2x+1` | 2.000, 1.002 | 2.000, 1.000 | 1,221 | 0.000002 |
| 잡음 데이터(음의 기울기) | −1.498, 7.969 | −1.498, 7.971 | 2,323 | 0.000001 |
| 대규모 스케일(수십만 단위) | 247.70, 245430 | 247.73, 245375 | 1,474 | MSE비 1.0000 |

**대규모 스케일에서도 정확한 것이 핵심입니다.** 학습을 정규화된 좌표에서 수행하기 때문에
값의 크기와 무관하게 수렴합니다.

### ✅ 역정규화가 수학적으로 정확
```javascript
const rw = this.model.w * (rY / rX);
const rb = (-this.model.w * b.minX / rX + this.model.b) * rY + b.minY;
```
`y = (w·(x−minX)/rX + b)·rY + minY` 를 전개한 것과 정확히 같습니다.
화면에 보이는 `y = ax + b` 가 **원래 데이터 단위**의 수식이고, MSE도 원래 단위로 계산합니다.
학생이 축의 숫자와 수식을 대조해 볼 수 있습니다.

## B. 시각화 정합성 — 상 (수정 없음)

- 캔버스에 데이터점·회귀선·잔차를 함께 그립니다.
- 예제 4종(공부시간→점수, 기온→아이스크림, 연습→게임점수, 거리→WiFi속도)이 있고,
  마지막 하나가 **음의 상관**이라 "기울기가 음수인 경우"도 다룹니다. 좋은 구성입니다.
- 수렴하면 버튼이 "학습 완료 (수렴)"으로 바뀌고 비활성화됩니다.

## C. 안정성 — 상 (수정 없음)

경계 케이스 전수 시험 결과 **예외·NaN·발산 0건**:

| 케이스 | 결과 |
|---|---|
| 점 1개 | 수렴(97회). 그 점을 지나는 직선 |
| 수직선(x 전부 동일) | 수렴(89회). 절편이 y 평균 = 5.0 — 최소제곱 정답 |
| 수평선(y 전부 동일) | 수렴(818회). `y = -0.00x + 5.00` |
| 동일점 3개 | 수렴(85회). 그 점을 지나는 직선 |
| 극단 스케일 2점(0 ~ 10⁶) | 수렴(838회). `y = 1.00x + 25.21` |
| 데이터 0개 | 예외 없음. `y = ax + b` 표시 |

`getBounds()`가 `minX === maxX`일 때 ±5로 벌려 **0으로 나누기를 막고 있습니다.**
정규화 단계에서 NaN이 생기지 않는 것을 확인했습니다.

> 점 1개·동일점처럼 해가 무수히 많은 경우 임의의 직선이 나오는데, 이는 문제 자체가
> 미결정이라 수학적으로 옳은 동작입니다. 다만 학생이 점 하나만 찍고 "왜 이런 선이 나오지?"
> 할 수 있어, 점이 2개 미만일 때 안내 문구를 띄우면 더 좋겠습니다(미수정).

## D. 접근성·반응형 — 중 → 상

### 🔴 D-1. 예제 설명이 모바일에서 전부 잘려 있었음 (수정)

`#exampleDesc`가 `h-5`(20px) **고정 높이**인데, 375px에서 설명이 세 줄(48px)이 됩니다.
**예제 4개 전부 잘려서 안 보이는 상태**였습니다.

| 예제 | 상자 | 내용 | 잘림 |
|---|---|---|---|
| 밤샘 공부 시간이 늘어나면 시험 점수가… | 20px | 48px | **잘림** |
| 기온이 높아질수록 아이스크림 판매량이… | 20px | 48px | **잘림** |
| 게임 연습 시간이 늘어날수록… | 20px | 48px | **잘림** |
| 공유기에서 멀어질수록 WiFi 속도가… | 20px | 48px | **잘림** |

데이터가 무엇을 뜻하는지 알려 주는 유일한 문구라 영향이 큽니다.

**수정**: `h-5` → `min-h-5` + `leading-snug break-keep`.
검증 결과 상자 44px / 내용 44px, **4개 모두 잘림 없음**.

### ✅ 좋은 점
- **캔버스가 이미 `pointerdown`을 사용** — 터치로 점 찍기가 됩니다.
- 작은 글자 사용이 거의 없습니다(`text-sm` 1곳). 나머지는 `text-base` 이상.
- 375px 가로 넘침 없음, 콘솔 에러 0건.
- `window.resize`에 캔버스 리사이즈가 연결되어 있습니다.

## 권고 → 해결됨 (아래 '추가 기능' 참조)

**학습률(learning rate) 조절 UI가 없습니다.** `this.learningRate = 0.05`로 고정되어 있습니다.
경사하강을 가르칠 때 "학습률이 너무 크면 발산하고 너무 작으면 느리다"는 것이 핵심 개념 중
하나인데, 지금은 그 실험을 할 수 없습니다. 슬라이더 하나를 붙이면 교육 가치가 크게 오릅니다.
다만 이는 버그 수정이 아니라 기능 추가라 이번 작업에는 넣지 않았습니다.

## 추가 기능 (2026-08-03, 사용자 승인 후)

### 학습률(α) 슬라이더 추가

경사하강 단원의 핵심 개념인 **"학습률이 크면 발산하고 작으면 느리다"** 를 학생이 직접
실험할 수 없던 문제를 해결했습니다. 기존에는 학습률이 코드에 고정되어 있었습니다.

- 로그 스케일 슬라이더 + 현재 값 표시 + 구간별 안내 문구(색상 구분)
- 값이 무한대로 튀면 **발산으로 감지해 안전하게 멈추고** 이유를 알려 줍니다.
  발산은 실패가 아니라 관찰 대상이므로 버튼을 다시 누를 수 있게 열어 둡니다.

| 슬라이더 | 학습률 | 반복 | 결과 | 기울기 | 안내 문구 |
|---|---|---|---|---|---|
| 10 | 0.0022 | 47,578 | 수렴 | 2.006 | 너무 작습니다 |
| 25 | 0.0071 | 15,620 | 수렴 | 2.006 | 너무 작습니다 |
| 50 (기본) | 0.05 | 2,219 | 수렴 | 2.006 | 적당합니다 |
| 80 | 0.52 | 194 | 수렴 | 2.006 | 다소 큽니다 |
| 100 | 2.50 | 8 | **발산** | — | 너무 큽니다 |

부수 수정: `enableTraining()` 이 `state-complete` 등 상태 클래스를 지우지 않아
초기화 후에도 버튼 색이 남던 기존 문제도 함께 고쳤습니다.

**핵심**: 수렴한 모든 경우에서 결과가 동일합니다. 학습률은 **정확도가 아니라 속도와 안정성**을
바꾼다는 점이 수치로 드러납니다.
