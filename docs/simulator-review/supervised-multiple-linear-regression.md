학생이 "다항회귀 = 제곱·세제곱 항을 추가하는 것"이라고 읽은 직후 실습을 누르면,
"여러 개의 원인(x₁, x₂)"에 대한 시뮬레이터가 열립니다. **서로 다른 개념입니다.**

### 선택지 (이번 작업에서는 손대지 않음)
1. 링크 라벨과 강의노트 설명을 **"다중선형회귀"** 로 바로잡고, 다항회귀 실습은 없다고 정리
2. 시뮬레이터에 **x² 항을 쓰는 다항회귀 모드**를 추가 (기능 개발)
3. 파일명을 바꾸기 — 단, `index.html`·강의노트 링크가 깨지고 학생이 북마크했을 수 있어 권하지 않음

강의 구성에 대한 판단이 필요하고 다른 파일 2개를 함께 고쳐야 해서, 지금은 보고만 드립니다.

## A. 개념 정확성 — 상 (수정 없음)

### ✅ 다변수 경사하강이 정확
```javascript
dw1 += err * p.x1;   dw2 += err * p.x2;   db += err;
dw1 = (2/N)*dw1; ...
```
MSE의 각 편미분과 정확히 일치합니다.

### ✅ 결과가 정규방정식 닫힌 해와 일치
가우스 소거로 푼 3변수 정규방정식과 대조:

| 데이터 | 학습 (w₁, w₂, b) | 닫힌 해 | 반복 | MSE |
|---|---|---|---|---|
| 정확한 평면 `2x₁+3x₂+5` | 2.000, 2.999, 5.002 | 2, 3, 5 | 2,189 | 0 / 0 |
| 잡음 데이터 | 1.456, −2.051, 7.359 | 1.457, −2.051, 7.356 | 1,902 | 0.5479 / 0.5479 |

### ✅ 음의 가중치도 정확히 학습
두 번째 케이스의 w₂ = −2.05. "가중치가 음수면 결과가 감소한다"는 핵심 정리와 화면이 일치합니다.

## B. 시각화 정합성 — 중 → 상

### ✅ 좋은 설계 — 2D 캔버스 2개로 3D 평면을 보여 줌
다중회귀는 본질적으로 3차원인데, `x₁–y` / `x₂–y` 두 개의 2D 그래프로 나눠 그립니다.
그리고 각각에 **"* x₂는 평균값으로 고정하여 추정한 선입니다"** 라는 해석 주석을 답니다.
이 주석은 오개념을 막는 결정적 정보입니다.

### 🔴 그런데 그 주석이 10px이었음 (수정)
`text-[10px]`로 하드코딩되어 사실상 읽을 수 없었고, 우하단에 겹쳐 있었습니다.
**하단 캡션 바(`text-base`, 반투명 배경, `pointer-events-none`)로 바꿨습니다.**
차지 면적은 그래프의 11%로 데이터를 가리지 않습니다.

## C. 안정성 — 상 (수정 없음)

### ✅ 에포크 상한이 오작동하지 않음
`if (this.epoch > 3000) return true;` — 상한에 걸려도 "학습 완료(수렴)"로 표시되므로,
실제로 걸리면 거짓 보고가 됩니다. 걸리는지 시험했습니다.

| 케이스 | 종료 사유 | 에포크 |
|---|---|---|
| x₂ ≈ x₁ (강한 다중공선성) | **기울기 수렴** | 1,136 |
| 스케일 1 vs 10,000 | **기울기 수렴** | 1,176 |
| 정확한 평면 | 기울기 수렴 | 2,189 |
| 잡음 데이터 | 기울기 수렴 | 1,902 |

**모두 상한 전에 정상 수렴**합니다. 정규화된 좌표에서 학습하기 때문입니다. 문제없습니다.

- `trainStep`이 `points.length < 2`면 즉시 종료 — 미결정 문제를 피합니다.
- 콘솔 에러 0건.

## 추가 기능 (2026-08-03, 사용자 승인 후)

### 학습률(α) 슬라이더 추가

경사하강 단원의 핵심 개념인 **"학습률이 크면 발산하고 작으면 느리다"** 를 학생이 직접
실험할 수 없던 문제를 해결했습니다. 기존에는 학습률이 코드에 고정되어 있었습니다.

- 로그 스케일 슬라이더 + 현재 값 표시 + 구간별 안내 문구(색상 구분)
- 값이 무한대로 튀면 **발산으로 감지해 안전하게 멈추고** 이유를 알려 줍니다.
  발산은 실패가 아니라 관찰 대상이므로 버튼을 다시 누를 수 있게 열어 둡니다.

| 슬라이더 | 학습률 | 결과 | w₁, w₂ | 안내 문구 |
|---|---|---|---|---|
| 5 | 0.0015 | 3000회 상한 (미수렴) | −0.61, −1.64 | 너무 작습니다 |
| 25 | 0.0071 | 3000회 상한 (미수렴) | 1.95, −1.12 | 너무 작습니다 |
| 50 (기본) | 0.05 | 수렴 (1,978) | **1.98, −1.49** | 적당합니다 |
| 70 | 0.24 | 수렴 (341) | **1.98, −1.49** | 적당합니다 |
| 85 | 0.77 | **발산** | — | 너무 큽니다 |
| 100 | 2.50 | **발산** | — | 너무 큽니다 |

(기대값 w₁ = 2, w₂ = −1.5)

**함께 고친 것 2가지**

1. `init()` 이 `learningRate` 를 0.05 로 되돌려, 슬라이더를 움직여도 학습 시작 순간
   기본값으로 리셋되던 문제. 학습률을 생성자로 옮겼습니다.
2. 3000 에포크 상한에 걸려도 **"학습 완료"** 라고 표시하던 문제. 상한 도달은 아직 수렴하지
   않았다는 뜻이므로 `3000회 도달 (아직 수렴 전)` 으로 구분해 표시합니다.
   학습률을 낮게 잡으면 실제로 도달하는 구간이라 필요한 수정이었습니다.

변수가 2개라 단일 회귀보다 낮은 학습률에서 발산합니다(0.6 수렴 / 0.8 발산).
안내 문구 구간을 이 실측에 맞춰 조정했습니다.

**핵심**: 수렴한 모든 경우에서 결과가 동일합니다. 학습률은 **정확도가 아니라 속도와 안정성**을
바꾼다는 점이 수치로 드러납니다.
