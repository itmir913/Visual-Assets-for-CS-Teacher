## A. 개념 정확성 — 상 (수정 없음)

### ✅ 추론이 건전(sound)함을 실측으로 확인

이 시뮬레이터의 핵심은 "논리적 추론으로 안전을 확정한다"입니다. 그 주장이 **실제로 참인지**를
무작위 세계에서 검증했습니다.

| 항목 | 5×5, 100회 |
|---|---|
| 금괴 획득 | 49 |
| 사망 | 51 |
| **안전하다고 판단한 칸에서 죽은 경우** | **0건** |
| **안전한 대안이 있는데 위험한 칸을 고른 경우** | **0건** |

즉 에이전트가 `safe`로 결론 낸 칸은 **한 번도 틀리지 않았고**, 죽은 51번은 전부
"안전 확정 칸이 하나도 없어 불가피하게 위험을 감수한" 경우였습니다. 추론 규칙과 행동 정책 모두
정확합니다.

### ✅ 추론 규칙이 교과서와 일치
- `¬Breeze` → 인접 칸 전부 `pitSafe`
- `¬Stench` → 인접 칸 전부 `wumpusSafe`
- `Breeze` / `Stench` → 미방문 인접 칸을 `possiblePit` / `possibleWumpus` 후보로
- `safe = pitSafe ∩ wumpusSafe` (교차 검증)

부정(`¬`)으로 안전을 확정한다는 점이 헤더 문구("'아님'을 뜻하는 기호 ¬(not)를 사용하여")와
정확히 맞습니다.

### ✅ 경로 탐색이 이미 방문한 칸만 통과
`getPathToTarget`의 BFS가 `agent.visited.has(ak) || isTarget` 조건으로만 확장합니다.
미지의 칸을 밟고 지나가는 일이 없습니다. 올바른 구현입니다.

### 사망률 40~50%는 버그가 아님
15% 확률로 함정이 배치되므로, 정보가 부족한 상태에서 위험을 감수해야 하는 상황이 자주 옵니다.
**"논리적으로 추론해도 정보가 부족하면 확실할 수 없다"** 는 것 자체가 이 단원의 핵심 메시지이고,
로그에 `확실한 길이 없어 위험 감수하고 (x, y) 탐색` 이라고 명시적으로 남습니다. 적절합니다.

### 참고 — 미구현된 추론 (미수정)
두 곳의 Stench로 괴물 위치를 한 점으로 좁히는 **삼각측량**은 구현되어 있지 않습니다.
이걸 넣으면 사망률이 내려가겠지만, 고등학교 수준에서 "부정으로 안전을 확정한다"까지가
적정 범위라고 판단해 그대로 두었습니다. 현재 구현도 논리적으로 틀린 곳은 없습니다.

## B. 시각화 정합성 — 상 (수정 없음)

- **지각(SENSE) → 추론(INFER) → 행동(MOVE)** 3단계를 상태 머신으로 분리하고 각각 로그를 남깁니다.
  `[1. 지각] (0,0): 💨 Breeze` → `[2. 추론] ¬Stench → 인접 칸 괴물 없음` → `[3. 행동] …`
  단계별로 눌러 보며 추론 과정을 따라갈 수 있습니다.
- 지식베이스(KB) 패널이 안전/위험 후보 칸을 실시간으로 보여 줍니다.
- 격자에 방문/안전/위험 후보가 색으로 구분됩니다.

## C. 안정성 — 중 → 상

### ✅ 무한 루프·교착 없음
5개 크기(4~8) × 40회씩 총 200회 완주 시험에서 **"길 막힘" 종료 0건, 미종료 0건, 콘솔 에러 0건**.
모든 판이 정상 종료했습니다. 목표를 못 찾는 경우의 강제 종료 처리도 이미 들어가 있습니다.

### 🟡 편향된 셔플 관용구 (수정)
```javascript
candidates.sort(() => Math.random() - 0.5);
```
비교 함수가 일관성 규약을 어겨 실제로는 한쪽으로 치우친 순서가 나옵니다(잘 알려진 안티패턴).
위험도·거리가 모두 같을 때의 무작위 타이브레이크에만 쓰이므로 영향은 작지만,
**Fisher-Yates**로 교체했습니다.

교체 후 추론 건전성 재검증: 안전 판단 오류 0건, 안전 대안 무시 0건 (100회).

## D. 접근성·반응형 — 하 → 중상

### 🔴 D-1. 모바일에서 격자가 246px로 쪼그라듦 (수정)

`.section-card`의 `padding: 2.5rem`(40px)이 `main`의 `px-6`(24px)와 겹쳐,
375px 화면에서 **좌우로만 128px**을 잃고 있었습니다.

```
375px − (24+24) − (40+40) = 247px
```

8×8을 고르면 칸이 **20×20px**까지 줄어 사실상 판을 읽을 수 없었습니다.

**수정**: `.section-card` 패딩을 모바일 `1.25rem`, 640px 이상에서 `2.5rem`으로 분리.

| | 수정 전 | 수정 후 |
|---|---|---|
| 격자 폭 | 246px | **286px** |
| 8×8 칸 | 20px | 25px |
| 6×6 칸 | 27px | 36px |
| 4×4 칸 | 43px | **57px** |

이 클래스는 페이지 전체 섹션에 쓰이므로 본문 가독성도 함께 개선됩니다.

### 🔴 D-2. 좌표 라벨이 8px (수정)
```javascript
const coordTextSize = SIZE <= 5 ? 'text-[0.7rem]' : 'text-[0.5rem]';
```
`0.5rem` = **8px**. 6×6 이상에서 좌표가 사실상 안 보였습니다.
`text-xs`(12px) / `text-[0.625rem]`(10px)로 상향했습니다. 라벨이 칸을 넘지 않는 것도 확인했습니다.

### ✅ 좋은 점
- `<body class="text-xl">` — 본문 기본 20px로 넉넉합니다.
- 조작이 버튼(단계 실행 / 자동 / 리셋) 기반이라 격자를 직접 터치할 필요가 없습니다.
  칸이 작아도 조작성 문제는 없습니다.
- 로그 패널에 `overflow-y: auto` 적용됨.
- 375px 가로 넘침 없음(수정 전후 모두).

## 남긴 항목 (미수정)

- **8×8 판의 좌표 라벨 10px** — 375px에서 칸이 25px이라 물리적 한계입니다.
  모바일에서는 4×4·5×5(칸 57px/44px, 라벨 12px)를 권하는 안내가 대안입니다.
