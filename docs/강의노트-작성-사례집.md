### 1-2. 절을 나눌 때는 래퍼 구조부터 본다

2026-08-06 인공지능기초 개정에서 이 구별을 놓쳐 **두 번 깨뜨렸다.**

**① 래퍼 하나에 `<hr>`로 나뉜 구조** — 래퍼를 닫았다가 새 절에서 다시 연다.

```html
<section id="intro">
    <div class="section-card space-y-8">     <!-- 이 래퍼를 -->
        <div>…첫 블록…</div>
        <hr class="border-slate-100">         <!-- 여기서 자르고 -->
        <div>…둘째 블록…</div>
    </div>
</section>
<!-- ↓ 나눈 뒤 -->
<section id="intro">
    <div class="section-card space-y-8">
        <div>…첫 블록…</div>
    </div>                                    <!-- 닫고 -->
    …스스로 확인 밴드…
</section>
<section id="integrate">
    …h2 · 부제…
    <div class="section-card space-y-8">      <!-- 다시 연다 -->
        <div>…둘째 블록…</div>
    </div>
</section>
```

**② 블록이 각자 `section-card`인 형제 구조** — 그냥 자르면 된다.

**정규식으로 `<div>` 스택을 세지 마라.** 이 저장소에는 여는 태그가 여러 줄에 걸친 `<div>`가
흔하다(「스스로 확인」 밴드가 대표적). `<div[^>]*>`로는 그 태그가 안 세어져 스택이 어긋난다.

```html
<div class="bg-gradient-to-r from-sky-50 to-slate-50 border border-sky-200
            border-l-4 border-l-sky-500 rounded-2xl px-6 py-5
            flex flex-col sm:flex-row gap-4 items-start sm:items-center">
```

### 1-5. `<sup>` `<sub>` 금지

2026-08-05 데이터과학 `3-2-2`에서 7곳, `3-1-1`에서 4곳 발견. 브라우저 실측으로만 잡혔다.

```html
<p>오차<sup>2</sup></p>        <!-- X : 12px로 렌더링된다 -->
<p>오차&sup2;</p>              <!-- O : 본문 크기 그대로인 위첨자 글자 -->

<p>y = a<sub>1</sub>x<sub>1</sub> + …</p>          <!-- X -->
<p>독립 변수 하나마다 계수가 하나씩 붙는다</p>        <!-- O : 문장으로 푼다 -->
```

제곱은 `&sup2;`(`3-1-2`의 `r&sup2;`가 선례). 아래첨자는 대응 문자가 마땅치 않아 **문장으로 푼다.**

### 1-6. 사이트 주소는 하이퍼링크로

2026-08-05 지적. 데이터과학 3개 파일 **13곳** 일괄 적용.

```css
a.ext-link { color:#4338ca; font-weight:600; text-decoration:underline;
             text-underline-offset:2px; word-break:break-all; }
a.ext-link:hover { color:#312e81; }
```

```html
<a class="ext-link" href="https://www.kaggle.com/datasets/geoffnel/evs-one-electric-vehicle-dataset"
   target="_blank" rel="noopener noreferrer">kaggle.com/datasets/geoffnel/evs-one-electric-vehicle-dataset</a>
```

`word-break: break-all`이 없으면 **긴 주소가 375px를 뚫는다.**
표시 글자는 `https://www.`를 뺀 짧은 형태, `href`에는 전체 주소.

### 1-7. 목록은 `list-outside`

`list-inside`는 마커가 콘텐츠 박스 안에 들어가 **줄바꿈된 둘째 줄이 번호 아래 맨 왼쪽으로 붙는다.**
좁은 화면일수록 줄바꿈이 잦아 더 자주 깨진다.

원문자(`①②③`)를 쓰지 않는 이유 — 보조기기가 읽는 방식이 제각각이고, 항목을 넣거나 빼면
손으로 다시 매겨야 하며, 글꼴 폴백 시 두부(□)로 깨진다.
(2026-08-04 전 과목 24개 파일 일괄 교정 완료)

### 1-8. 코드 블록 가로 넘침

2026-08-04 `<pre>` 사용 **50개 파일** 일괄 적용. 적용 전 **39개 파일이 무방비**였다.
적용 후 375px에서 50개 전부 가로 넘침 0 확인.

`white-space: pre-wrap`으로 접지 않는 이유 — 코드는 들여쓰기가 의미를 가지므로 원형을 지키고
스크롤을 코드 블록 안에 가둔다. 래퍼 `div`를 끼우면 코드 블록 마크업이
`rounded-xl overflow-hidden`·`flex-1`·탭 콘텐츠 등으로 제각각이라 둥근 모서리와 레이아웃이 깨진다.

### 1-9. hero `<h1>`에 `<br>`을 넣지 않는다

줄을 어디서 끊을지 사람이 정하면 화면 폭이 달라질 때마다 어긋난다. 브라우저에 맡긴다.
`<h1>` 안의 문자열이 곧 `<title>`과 같아야 하므로 **제목 네 곳을 대조하기도 이쪽이 단순하다.**

2026-08-11 세 과목 83개 파일에서 `<br>`을 빼고 `break-keep`을 넣었다.
hero 부제(`<p>`)의 `<br>`은 문장이 둘로 나뉘는 자리라 그대로 쓴다.

### 1-10. `스스로 확인` 밴드는 카드 바깥

두 과목 51개 파일 기준 **바깥 225 / 안 35.** 바깥이 관행이고,
안에 있는 35개는 예외가 아니라 고쳐야 할 것들이다.

카드 안에 넣으면 본문의 일부처럼 보여 **「읽고 나서 멈추는 자리」라는 성격이 사라진다.**
학생은 카드 안의 것을 그냥 이어 읽는다.

### 1-11. 코드 요소의 한글 글꼴이 시스템 기본으로 떨어진다

요소 선택자(`code, pre { … }`)만 쓰면 **Tailwind의 Preflight에 밀린다.**
CDN을 쓰던 때는 런타임 주입이라 늘 뒤에 왔고, npm+Vite로 옮긴 뒤에도 구워진
스타일시트가 인라인 `<style>` 뒤에 놓여 사정이 같다. `body`를 앞에 붙여 특정도를 올리면 이긴다.

라틴 문자는 모노스페이스로, 한글은 Pretendard로 떨어지게 하는 것이 목적이다.
폰트 스택에서 한글 폰트를 모노스페이스 뒤에 두면 그렇게 된다.

### 1-12. 「이전 차시 · 다음 차시」 링크를 만들지 않는다

파일 이름이나 차시 순서가 바뀔 때마다 **앞뒤 파일을 함께 고쳐야 한다.**
차시 하나를 둘로 나누면 고칠 파일이 셋이 된다. 이동은 푸터의 목록 링크로 충분하다.

본문에서 「다음 시간에 배운다」고 **글로 예고하는 것은 괜찮다** — 링크가 아니라서 깨지지 않는다.

### 1-13. 코드를 HTML 안에 두지 않는 이유

프로그래밍 44개 파일의 코드블록 **276개**(평균 8.3줄)를 조사한 결과다.
수동 하이라이팅 span은 이미 0개라 **Prism 탓이 아니었다.** 진짜 원인은 둘이었다.

1. **이스케이프 불일치** — `&lt;` 138건, `&gt;` 103건. 그중 **5개 블록은 같은 블록 안에서**
   주석의 `<`는 raw, 코드의 `<`는 `&lt;`였다. 브라우저에서 똑같이 보이므로
   **복사해서 고치는 것이 불가능했다.**
2. **`onclick="copyCode('code-98')"`** — id 95개가 파일을 넘어 중복.

실파일로 빼면 편집기가 문법을 알고, 검사기가 구문 오류를 잡고,
학생이 내려받는 파일과 화면에 뜨는 코드가 같아진다.

### 1-14. 배포 산출물을 둘로 나누지 않는다

**로컬화를 하는 이유부터** — 학교망은 CDN을 막는 경우가 많다. 배포되는 사이트 자체가
로컬화된 번들이어야 **CDN을 막는 학교망에서도 수업이 된다.** 오프라인 zip은 덤이 아니라
같은 목적의 다른 배달 방법이다.

예전에는 Pages용(CDN 유지)과 릴리즈 zip용(로컬화)을 따로 만들었다.
**zip은 아무도 열어 보지 않아 결함이 그쪽에만 쌓였다.**

실제로 `프로그래밍(Python)/1-1-2`에서 런타임에 조립된 클래스 8개 중 **3개가 zip에서만 빠진 채**
오래 남아 있었다. 소스를 그대로 열면 CDN 런타임 JIT라 멀쩡히 보이므로 눈으로는 잡히지 않았다.

같은 파일을 서빙하면 **사이트를 보는 사람이 곧 번들의 검증자가 된다.**
2026-08-11에 하나로 합쳤다.

**그래도 「같은 파일」이 「같게 동작한다」는 뜻은 아니었다.** 합친 뒤에도 zip에서만
깨지는 것이 남아 있었다 — `<script type="module">`이다. 모듈은 CORS를 타는데
`file://`의 출처는 `null`이라 브라우저가 무조건 거절한다. 라이브러리가 실리지 못해
시뮬레이터의 그래프·트리·차트가 통째로 안 그려졌는데, **사이트에서는 멀쩡했다.**
2026-08-19에 빌드가 평범한 스크립트로 눌러 담게 고치고, 모듈이 다시 새어 나가면
`check:dist`가 CI를 세우게 했다. **배달 방법이 둘이면 검사도 둘 다를 봐야 한다.**

### 1-15. SVG 글자 크기 — 바닥만 있고 천장이 없었다

`min-width`(모바일에서 줄어들지 않게 하는 바닥)는 챙기면서 `max-width`(데스크톱에서
커지지 않게 하는 천장)는 빠뜨리기 쉽다. 375px만 보고 고치기 때문이다.

2026-08-11 감사 도구를 고치기 전에는 **24건이 걸렸는데 실제 결함은 1건**이었다.
도구가 `style`의 `max-width`만 보느라 아래를 전부 결함으로 세었다.

| 이미 묶여 있던 것 | 왜 괜찮은가 |
|---|---|
| `class="… max-w-2xl mx-auto"` | Tailwind 클래스도 천장이다. 정규식 끝의 `\b`가 `max-w-[200px]`의 `]` 뒤에서 서지 않아 통째로 놓쳤다 |
| `width="100" height="70"` | 값이 박혀 있으면 아예 늘어나지 않는다 |
| `style="max-height:260px"` | 높이가 묶이면 `preserveAspectRatio` 때문에 배율도 함께 묶인다 |
| 높이 고정 부모 + `class="h-full"` | 같은 이유 |

**가운데 정렬도 폭 천장이 있을 때만 문제가 된다.** 높이로 묶인 그림은 남는 자리가
좌우로 생기는데 `preserveAspectRatio` 기본값(`xMidYMid`)이 이미 가운데 놓는다.
폭 천장이 걸려 SVG **요소 자체가** 부모보다 좁아질 때만 왼쪽에 붙는다.

**감사 도구가 시끄러우면 도구부터 고친다.** 24건을 그대로 믿고 고쳤다면
이미 멀쩡한 23곳에 쓸데없는 속성을 붙이고, 진짜 한 건은 그 속에 묻혔을 것이다.

### 1-16. CDN에서 npm + Vite로 — 밟은 함정 넷

2026-08-11에 소스 HTML의 CDN을 전부 걷어냈다. 옮기는 것 자체보다 **옮긴 뒤에
조용히 깨지는 것**을 찾는 데 시간이 들었다.

| 함정 | 어떻게 드러났나 |
|---|---|
| **npm 판과 CDN 판의 API가 다르다** | lucide UMD는 `createIcons()`만으로 됐지만 npm 판은 아이콘 목록을 받는다. 콘솔 오류가 나서 바로 잡혔다 |
| **최상위 `await`는 `window.onload`보다 늦다** | Prism 언어 확장을 동적 import로 붙였더니 하이라이팅이 **조용히** 실패했다. 오류도 없고 토큰만 0이었다 |
| **모듈은 defer라 인라인 스크립트보다 늦다** | 인라인에서 라이브러리를 바로 부르는 파일을 찾아야 했다. **들여쓰기로 세면 48개, 괄호 깊이로 세면 1개** — 앞의 것은 `window.onload` 안까지 센 과대추정이었다 |
| **버전을 안 맞추면 조용히 깨진다** | npm 기본이 Font Awesome 7(아이콘 이름 변경), p5 2.x(호환 깨짐)였다. **소스가 쓰던 CDN 주소의 버전으로 못박았다** |

**되는지는 브라우저로만 확인된다.** 클래스 대조와 링크 검사는 전부 통과했는데도
하이라이팅이 죽어 있었다. 라이브러리를 옮겼으면 대표 페이지를 실제로 띄워 본다.

```
O  (목표) 줄어드는 일과 새로 생기는 일의 특징을 구분할 수 있다
```

**반대 방향도 본다** — 2026-08-06 `2-2-1`은 목표에 「순전파·역전파」가 있는데
**본문에 역전파라는 낱말이 없었다.**

(2026-08-06 인공지능기초 `2-2-1`·`3-1-3`·`3-2-1` 세 파일.)

## 3. 그 밖의 서술 규칙

### 3-1. 용어의 한국어·영어 표기는 한 줄에

(2026-08-05 사용자 지적. 데이터과학 `3-1-1`·`3-1-2` **7곳** 교정.)

핵심 정리 카드의 `<h3>` + 부제 패턴은 예외다(`데이터 시각화` / `data visualization`).
카드 헤더 관례라 저장소 전반이 그렇게 되어 있다.

### 3-2. 짝을 이루는 개념은 나란히

2026-08-05 사용자 제안. 회귀·분류를 2열로 놓자 **「둘 다 선을 긋는다」는 오개념이 드러났다.**

2026-08-06 인공지능기초 `2-1-6`이 이 처방을 그대로 썼다 —
같은 `viewBox`로 두 그림을 그리고 소제목을 **「점들을 지나는 선」 / 「점들을 가르는 선」**으로
대구를 맞춘 뒤, 회귀의 선은 **값을 읽는 자**이고 분류의 선은 **갈래를 가르는 울타리**라는
상자를 뒀다.

### 3-2-1. 교과가 겹치면 「정보」 쪽 서술로 맞춘다

(2026-08-22 사용자 확정. 다섯 건 교정.)

정보는 모든 학생이 듣는 공통 과목이고 인공지능기초·데이터과학이 그 위에 얹힌다.
**먼저 배운 말이 뒤에서 바뀌면 앞을 제대로 배운 학생이 걸려 넘어진다** → 2장의 「4·7번」.

교과서끼리 다를 때도 정보를 따르되, **교과서 근거를 먼저 확인한다.** 실제로 확인해 보니
어긋난 쪽이 근거가 없는 경우가 있었다 — 인공지능기초 강의노트가 쓰던 지능 에이전트의
특성 셋(자율성·협력성·목표 지향성)은 **그 교과서에 한 번도 나오지 않는 말**이었고,
정보 교과서에는 다섯(자율성·능동성·사회성·시간 연속성·반응성)이 실려 있었다.

| 어긋났던 것 | 어떻게 맞췄나 |
|---|---|
| 지도학습의 수치 유형 이름 | **회귀**. 두 교과서 모두 회귀다. 「예측」은 회귀가 **하는 일**을 말하는 동사 자리에만 쓴다 |
| 훈련/시험 데이터 | **훈련 데이터 · 테스트 데이터**. 「시험 데이터」는 두 교과서 어디에도 없던 말이었다 |
| 지능 에이전트의 정의 | 가르는 자리는 **학습과 추론이 있는가**. 학습을 요건에서 빼면 같은 기기를 두 교과가 다르게 판정한다 |
| 지능 에이전트의 특성 | **다섯**으로 통일 |
| 인공지능이 흉내 내는 능력 | **지각**(능력)과 **인식**(동작 단계)을 나눠 쓴다 |

**하나는 일부러 통일하지 않았다.** 동작 단계가 정보는 넷(인식→학습→추론→행동),
인공지능기초는 셋(인식→판단→행동)인데 **어긋난 것이 아니라 묶는 단위가 다르다.**
파일 전체가 3단계로 짜여 있어 다시 짜는 대신 **「판단은 학습과 추론을 함께 부르는 말」**
한 줄을 넣어 두 그림을 겹쳐 볼 수 있게 했다. **어긋남이 아닌 것을 억지로 맞추면
멀쩡한 구조가 무너진다.**

### 3-3. 예시 인물 익명화

강의노트는 웹에 올라가는 공개 자료다. **실명형 예시는 실제 재학생과 이름이 겹칠 때
당사자를 지목하는 것처럼 읽힌다.** 익명 표기는 표를 읽기 쉽게 만드는 부수 효과도 있다.

2026-08-06 인공지능기초에서 `1-2-4`·`2-1-2`·`2-2-3` 세 파일에 실명형이 남아 있었다.

### 3-4. 자체 서술 원칙

참고 자료 내부의 번호(`[표 Ⅱ-9]`, `[그림 Ⅱ-21]`)는 **그 자료 안에서만 뜻이 통한다.**
캡션은 **무엇을 담은 표인지**로 쓴다. HTML 주석에도 남기지 않는다.

```html
<p>[표 Ⅱ-9] 세계 행복 보고서 2023 중 일부</p>              <!-- X -->
<p>세계 행복 보고서 2023 데이터 일부 — 137개국 중 12개국</p>   <!-- O -->
```

`fa-quote-left` 인용 블록은 **실존 인물의 발언에만** 쓰고 발언자를 밝힌다.
일반 개념 정의에 인용 블록을 쓰면 출처를 밝혀야 하는데 개념에는 밝힐 출처가 없다.

```html
<!-- O : 인물 발언 + 발언자 -->
<p>… 발견하는 태도, 유연성, 자발성이 바로 탐색적 데이터 분석이다.
   <span>— 존 튜키(John Tukey)</span></p>
```
