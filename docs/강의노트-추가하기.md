# 강의노트를 추가하는 법

**새 차시 하나**, **새 과목 하나**, **새 배부 양식 하나**를 만들 때 각각 무엇을 해야 하는지.
지켜야 할 규칙은 [`CLAUDE.md`](../CLAUDE.md)에 있고, 이 문서는 **순서**만 다룬다.

과목마다 문서를 따로 두지 않는다. 절차가 과목별로 다른 부분은 **표 한 칸**이지
문서 하나가 아니기 때문이다. 나누면 규칙이 바뀔 때 다섯 군데를 고쳐야 한다.

---

## A. 새 차시 하나를 추가한다

### Write 도구로 처음부터 쓰지 않는다

2,000행짜리를 한 번에 쓰면 **느리고, 중간에 끊기면 전부 날아간다.**
hero · nav · 학습 목표 · 푸터 · 퀴즈 스크립트는 파일마다 거의 같으므로 매번 새로 쓰는 것은 낭비다.
(CSS는 파일에 없다 — 틀은 `src/styles/_note.css`와 과목 CSS에 있고, 강의노트에 `<style>`을 두지 않는다.)

**`docs/template-*.html` 같은 별도 템플릿 파일은 두지 않는다.** 규칙이 바뀔 때마다 템플릿도
같이 고쳐야 하는데 잊기 쉽다. 실제로 낡은 템플릿 두 개(`template-ai-class.html`,
`template-programming.html`)가 폐기된 디자인(검정 푸터, `Chapter 01` 배지, Lucide+`execCommand`)을
그대로 담은 채 방치돼 있다가 지워졌다(2026-08-06).

**규칙을 다 지킨 실제 파일을 그 과목의 기준으로 삼는다** — 최신 규칙은 항상 실제 파일에만 있다.

| 과목 | 기준 파일 | `index.html` 테마 |
|---|---|---|
| 인공지능기초 | `인공지능기초/3-2-4.사회적-책임과-공정성.html` | `theme-purple` |
| 데이터과학 | `데이터과학/2-2-2.데이터-시각화.html` | `theme-indigo` |
| 정보(고등학교) | `정보(고등학교)/1-1-1.네트워크란-무엇인가.html` | `theme-teal` |
| 프로그래밍 | `프로그래밍/py/09-파일-입출력.html` | `theme-orange` |
| 소프트웨어와생활 | `소프트웨어와생활/5-3-1.우리-아이디어를-내놓고-돌아보기.html` | `theme-lime` |

### 절차

1. **복사해서 껍데기 만들기** — 출력 0행

   ```bash
   cd 데이터과학
   cp 2-2-2.데이터-시각화.html 새파일.html
   node -e '
   const fs = require("fs"), p = "새파일.html";
   const s = fs.readFileSync(p, "utf8");
   const i = s.indexOf("<main "), j = s.indexOf("</main>");
   fs.writeFileSync(p, s.slice(0, s.indexOf(">", i) + 1) + "\n\n    <!-- 섹션은 여기에 하나씩 추가한다 -->\n\n" + s.slice(j));
   '
   ```

   hero · nav · footer · 퀴즈 스크립트가 전부 남는다. `table-prose` · `ext-link` · `chart-svg` 같은 틀은 공용 CSS에 있으니
   클래스만 쓰면 된다. 인공지능기초는 기준 파일의 `<header>` · `<body>`에 달린 `hero-…` · `quiz-…` 클래스를 그대로 쓴다
   (편마다 색을 새로 만들지 않는다 — 있는 클래스 가운데 고른다).

2. **정체성 부분만 교체** — title / hero 아이콘·제목·부제 / 학습 목표 / nav 아이콘·제목·링크 / footer

3. **커밋을 지시받았으면 여기서 커밋한다.** 이 시점부터 중단돼도 껍데기는 안전하다.

4. **섹션을 하나씩 Edit로 붙인다.** `<!-- 섹션은 여기에 하나씩 추가한다 -->`를
   `새 섹션 + 같은 주석`으로 바꾸면 계속 이어 붙일 수 있다.
   커밋을 지시받았으면 섹션 2~3개마다 커밋한다. 중단돼도 그 지점부터 재개할 수 있다.

5. 다 붙이면 주석을 지우고 검증한다(커밋은 지시받았을 때).

   ```bash
   npm run check -- html "데이터과학/새파일.html"
   ```

   **HTML의 `<head>`에는 CDN 주소를 쓰지 않는다.** 스타일 진입점 하나를 링크하고,
   라이브러리를 쓰면 `src/entries/`에 그 페이지 진입점을 만들어 함께 건다
   → [`tools/README.md`](../tools/README.md)의 「의존성은 전부 npm이다」.

6. **`index.html` 등록은 사용자가 지시할 때만 한다.** 먼저 등록하자고 말하지 않는다.

## B. 새 과목 하나를 추가한다

폴더만 만들면 **빌드도 배포도 되지 않는다.** 아래 셋을 함께 해야 한다.

1. **[`subjects.json`](../subjects.json)의 `subjects`에 한 항목.**
   **이것이 유일한 게이트다.** 여기 없는 폴더는 빌드가 보지 않으므로 사이트에도
   오프라인 zip에도 들어가지 않는다. 검사 스크립트도 Vite도 같은 파일을 보므로,
   빠뜨리면 **그 과목만 검사에서 통째로 새어 나간다** — 실제로 「정보(고등학교)」가
   한동안 그런 상태였다.

   ```json
   { "dir": "프로그래밍", "slug": "programming", "theme": "orange" }
   ```

2. **`src/tailwind/<slug>.config.js`와 `src/styles/<slug>.css`를 함께 만든다.**
   `programming.config.js` · `programming.css`를 복사해 이름과 과목 색만 바꾸면 된다. CSS 진입점은 이 모양이다.

   ```css
   @import "@fortawesome/fontawesome-free/css/all.min.css";
   @import "pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css";
   @import "prismjs/themes/prism-tomorrow.css";   /* 코드 블록이 있는 과목만 */
   @import "./_code-copy.css";   /* 코드 블록 복사 버튼 */
   @import "./_quiz.css";        /* 퀴즈 스크립트가 만드는 요소의 모양 */
   @import "./_theme.css";       /* 라이트 · 다크 테마 */
   @import "./_tailwind.css";    /* @tailwind 층(변형 포함) */
   @import "./_note.css";        /* 강의노트의 틀 — 반드시 _tailwind.css 뒤 */
   @config "../tailwind/<slug>.config.js";

   :root { --note-hero: …; --note-tint: …; --note-rim: …; --note-solid: …; /* 뜻은 _note.css 머리 주석 */ }
   ```

   `@config`로 그 과목만 가리켜야 다른 과목의 클래스가 섞여 들어오지 않는다. Tailwind 설정에는
   `presets: [theme(['<폴더>'])]`를 건다(다크의 색 짝). 토글은 빌드가 과목 폴더를 저절로 받는다.

3. **테마 색을 정한다.** 이미 쓰는 색과 겹치지 않게 한다(위 표).

4. **배부 양식이 있다면 [`tools/docx/outpath.js`](../tools/docx/outpath.js)의 `DEST`에 한 줄.**
   아래 C를 볼 것.

`index.html` 등록은 강의노트가 어느 정도 쌓인 뒤 **사용자가 지시할 때** 한다.
등록 전에도 `subjects.json`에만 있으면 주소로 열어 검토할 수 있다.

## C. 새 배부 양식(`.docx`) 하나를 추가한다

**절차는 [`tools/docx/README.md`](../tools/docx/README.md)에 있다.** 여기 옮겨 적지 않는다.

요점만 — 생성기 `make/<그룹>/<산출물 이름>.js`를 하나 만들고, 출력은 반드시 `out(그룹, 파일명)`으로
적는다. 경로를 파일에 직접 쓰지 않는다. 산출물은 **커밋하지 않는다** — 배포 빌드가 매번 만든다.

---

## D. 코드가 들어가는 강의노트라면

코드는 HTML에 쓰지 않고 **강의노트 옆 `code/`에 실파일로** 둔다.
마커와 구역 문법, 구문 검사에서 빼는 법은
[`tools/README.md`](../tools/README.md)의 「코드는 HTML에 넣지 않는다」에 있다.

## E. 참고 자료를 바탕으로 여러 차시를 쓴다

1. **쪽 오프셋부터 확정한다** — `PDF쪽 = 원본쪽 − OFFSET`. 다른 두 곳에서 검증하고 곧바로 적어 둔다.
   「단원이 시작하는 PDF 쪽」과 오프셋을 한 표에 섞어 적지 않는다(한 번 헛짚었다).
2. **TXT로 용어와 수치를 얻고, 같은 범위의 PDF 쪽을 연다.** TXT만 보면 도해 · 활동이 통째로 빠진다.
3. **차시를 가르고 사용자에게 먼저 보인다.** 참고 자료의 활동을 뺄 것이면 무엇을 왜 빼는지 함께 보고한다.
4. **에이전트 하나가 같은 소단원의 파일 2~3개를 맡는다.** PDF를 한 번만 읽게 하려는 것이다. 지시문에 넣을 것:
   - 담당 파일 이름, 다른 파일 수정 금지, `git` 쓰기 금지, 하위 에이전트 금지, 브라우저 · 웹 검색 금지
   - 읽을 **PDF 쪽** 범위
   - 앞 파일에서 세운 정의 목록(그대로 붙인다) — 파일 사이의 정의 불일치를 막는 가장 싼 방법이다
   - 원문 문장 · 쪽수 · 그림 번호 · 참고 자료 이름을 쓰지 않는다, 예시 · 비유 · 예시 값 · 예시 코드는 새로 짠다
   - 근거표는 파일로 쓰고 채팅 반환은 짧은 요약만
5. **에이전트가 끝나면 직접 확인한다** — `git status`(에이전트 보고가 사실과 다른 적이 있다) ·
   원문 대조(아래) · 수치와 코드 출력 재계산 · `npm run check -- html prose`.
6. 중단원마다 커밋하고 사용자 확인을 받는다.

**원문 대조** — 새로 쓴 본문과 원본 TXT를 **한글만 남기고 8자 연속 일치**로 본다. 태그를 지운 뒤 한 덩어리로
잇지 말고 요소 조각마다 따로 대조한다(퀴즈 보기 넷이 붙어 거짓으로 걸린다). 남아도 되는 것은 용어 나열 ·
공식 명칭 · 주소뿐이다.

**가장 자주 나온 실패 셋** — 앞 파일이 조건부로 세운 것을 뒤 파일이 무조건으로 되돌린다 · 파일 사이 역할이
겹쳐 같은 것을 두 번 배운다 · 제목 · 핵심 정리 · 퀴즈가 본문보다 단정하다. 오개념 규칙 7 · 4 · 8번이 이것이다.

## 다 하고 나서

```bash
npm run ci
```

검사 → 배포와 같은 빌드 → 산출물 검사를 한 번에 돌린다. CI가 하는 일과 같다.
