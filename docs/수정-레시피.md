# 알려진 수정 레시피

한 번 풀어 본 문제의 해법을 적어 둔다. 같은 증상을 다시 만났을 때 처음부터
다시 파헤치지 않으려는 것이다. **규칙이 아니라 해법이므로** 상황이 다르면 그대로 쓰지 않는다.

## 적은 토큰으로 고칠 때 — 무엇을 고치면 무엇을 돌리나

유지보수로 한두 곳만 고칠 때는 `npm run ci` 전체보다 고친 것에 맞는 검사만 먼저 돌린다.
각 도구의 인자와 출력 읽는 법은 **그 스크립트의 머리 주석**에 있다(`tools/run.mjs` ·
`tools/checks/<이름>.mjs` · `tools/audits/<이름>.mjs`). 여기에는 짝만 적는다.

| 고친 것 | 돌릴 것 |
|---|---|
| 강의노트 한 편의 글·마크업 | `npm run check -- html <파일>` → `npm run check -- prose` |
| 그 편의 SVG(글자·좌표) | 위에 더해 `npm run audit -- svg <폴더>` — `ci` 밖이라 고친 사람이 돌린다 |
| `code/`의 `.py`·`.c` 또는 `data-src` 마커 | `npm run check -- code` — 마커가 가리키는 파일 · 구역이 있는지는 빌드가 보므로 마커를 고쳤으면 `npm run build` 도 |
| 페이지 `<style>` · 인라인 스크립트 · `src/styles/` | `npm run check -- hover classes` |
| 시뮬레이터 한 장 | `npm run check -- sim <이름>` — `tools/run.mjs`의 `SIM_BY_NAME_ONLY`에 든 것은 이름 없이 부르면 빠지므로 **꼭 이름으로** |
| 시뮬레이터 화면 글(JS 문자열) | 위에 더해 `npm run check -- terms verbs prose` |
| 시뮬레이터 배치·크기 | 위에 더해 `npm run check -- layout` |
| 배부 양식 생성기(`tools/docx/make/`)의 문장 | `npm run check -- prose` → `npm run docx`. 짝 실습 HTML의 답안 상자와 문구가 같아야 하므로 그쪽도 함께 본다 |
| 루트 `index.html`의 시뮬레이터 목록 | `npm run gen:sim-index` 뒤 `npm run check` |

- **푸시 전에는 `npm run ci`** 하나. 초록일 때만 푸시한다.
- **배포는 손으로만** — `gh workflow run deploy.yml --ref master`. 푸시로는 배포되지 않는다.
- 검사가 빨간데 까닭을 모르겠으면 이 문서의 다른 절을 이름으로 찾는다(증상이 절 제목이다).

## 터치 드래그가 안 되는 격자·캔버스

`mousedown`/`mouseenter`만 바인딩하면 태블릿에서 드래그 조작이 되지 않는다.
포인터 이벤트로 바꾸되, **암묵 캡처를 반드시 해제해야 한다.**

```javascript
cell.addEventListener('pointerdown', onDown);
cell.addEventListener('pointerenter', onEnter);
document.onpointerup = document.onpointercancel = () => isDrawing = false;

function onDown(e) {
    // 터치는 첫 요소에 포인터가 암묵 캡처되어 이웃의 pointerenter가 발생하지 않는다 → 반드시 해제
    if (e.pointerId !== undefined && e.currentTarget.hasPointerCapture?.(e.pointerId)) {
        e.currentTarget.releasePointerCapture(e.pointerId);
    }
    ...
}
```

컨테이너에 `touch-action: none;`을 함께 지정해 드래그 중 페이지 스크롤을 막는다.

## 375px에서 섹션이 몇 화면인지 재기

**사용자가 지시했을 때만 잰다**(2026-08-19 확정). 파일을 다 썼다는 이유로 자동으로
띄우지 않는다 — 6화면은 글을 쓰는 동안 분량을 조절하라는 기준이지 통과해야 하는
관문이 아니다. 재지 않았으면 재지 않았다고 밝히면 된다.

브라우저 콘솔에서. **`clientWidth`가 정말 375인지 함께 찍어 확인한다** —
뷰포트가 바뀐 채로 재면 값이 전부 틀린다.

```javascript
[...document.querySelectorAll('main > section')].map(s => ({
    id: s.id, 화면수: +(s.getBoundingClientRect().height / 812).toFixed(1)
}))
```

재는 대상은 **소스가 아니라 빌드 결과다.** `npm run dev`로 띄우거나
`npm run build` 뒤 `dist/`를 연다.

## 여러 페이지를 375px에서 한꺼번에 재기

페이지마다 `navigate`를 부르면 왕복이 페이지 수만큼 든다. **375px짜리 iframe 하나를
띄워 놓고 `src`만 갈아 끼우면** 브라우저 도구 호출 서너 번으로 끝난다.

```javascript
const f = document.createElement('iframe');
f.style.cssText = 'position:fixed;left:0;top:0;width:375px;height:812px;border:0;z-index:9999';
document.body.appendChild(f);
for (const p of pages) {
    await new Promise(r => {
        const t = setTimeout(r, 10000);                       // 안 뜨는 페이지 대비
        f.onload = () => { clearTimeout(t); setTimeout(r, 2500); };  // 그린 뒤에 잰다
        f.src = p;
    });
    const d = f.contentDocument;
    결과.push({ p, scrollW: d.documentElement.scrollWidth });  // 375 미만이면 가로 넘침 없음
}
```

- **결과를 `window`에 담아 두고 나중에 꺼낸다.** 도구가 프라미스를 기다려 주지 않는다.
- 첫 회차는 Vite가 페이지마다 새로 묶느라 느리다. **한 페이지에 5~10초**를 잡는다.

### 「뷰포트보다 넓은 요소」를 전부 결함으로 세지 않는다

표와 코드 블록은 **넓은 것이 정상이고 `overflow-x-auto`가 받아 준다.** 넓다는 것만으로
세면 멀쩡한 자리가 무더기로 걸린다. 넓은 요소를 찾았으면 **조상 쪽으로 올라가며
`overflow-x`를 보고 갈라야** 한다.

| 조상의 `overflow-x` | 뜻 |
|---|---|
| `auto` · `scroll` + `scrollWidth > clientWidth` | **정상** — 밀어서 볼 수 있다 |
| `hidden` | **잘려서 못 본다** — 다만 히어로의 장식 블롭은 일부러 이렇게 둔다 |
| 없음 | 페이지가 통째로 넘친다 — `scrollWidth`에도 함께 잡힌다 |

### 0×0 캔버스는 대개 숨은 탭 안이다

탭으로 나뉜 시뮬레이터는 **안 보이는 탭의 캔버스가 0×0으로 잡힌다.** 결함이 아니다.
조상 쪽으로 올라가며 `display:none`인 것을 찾아 **숨은 것인지 정말 찌부러진 것인지**
갈라 놓아야 「캔버스가 죽었다」는 헛다리를 짚지 않는다.

## 모바일에서 글이 한 줄에 서너 낱말씩만 들어갈 때

카드 안쪽 본문이 강제로 들여쓰기된 것처럼 보이고 줄이 잘게 끊긴다면,
**글꼴이 아니라 남은 폭의 문제다.** 375px에서 바깥 것들을 다 빼고 나면
본문에 100px대만 남아 있는 자리가 있다.

```bash
npm run audit -- narrow
```

`[아이콘]`으로 표시되면 **아이콘을 왼쪽에 세운 가로 배치**가 범인이고,
`[여백]`이면 여백이 여러 겹 겹친 것이다. 고치는 법은 CLAUDE.md의
「본문에 남는 폭」 항목에 있다.

**셈이 틀리기 쉬운 자리를 셋 밟았다.** 감사 결과가 이상하면 이것부터 의심한다.

| 함정 | 무슨 일이 나는가 |
|---|---|
| 폭이 안 적힌 flex 형제 | 「자란다」고 보면 **뱃지 한 칸짜리 열이 절반을 가져간다.** `flex-1`·`grow`가 붙은 것만 자란다 |
| `section-card !p-6` | `!important`가 카드 여백을 **지운다.** 둘 다 빼면 시뮬레이터가 통째로 헛걸린다 |
| 아이콘 칸 판정 | 폭 클래스가 제 몸이 아니라 **안쪽 `<span>`에** 붙어 있다. 「담긴 글자가 없다」로 가르는 편이 확실하다 |

**세로로 쌓은 뒤에는 반드시 가로 넘침을 다시 잰다.** `flex-col`로 바꾸면서 `items-start`를
그대로 두면 칸이 «내용 폭»으로 줄어들고, 안에 든 넓은 표가 페이지를 밀어낸다.
실제로 한 파일에서 **214px이 넘쳤고 `items-stretch`로 바꾸자 0이 되었다.**
계산기는 이것을 못 본다 — **`scrollWidth - clientWidth`를 브라우저에서 재야 나온다.**

되돌아오면 안 되는 두 자리(`.section-card` 여백 · `<main>` 여백)는
`npm run check -- html`이 지키므로 **감사를 잊어도 그 둘은 새지 않는다.**

## 캔버스에 글자가 «통째로» 안 보일 때

`ctx.font`에서 크기를 읽을 때 **`parseFloat`를 쓰면 안 된다.**

```js
parseFloat('bold 18px ui-monospace, …')   // NaN — «bold»로 시작한다
```

NaN으로 자리를 잡으면 좌표가 NaN이 되고 **그 글자는 아무 말 없이 사라진다.**
캔버스는 오류를 내지 않으므로 콘솔도 조용하다.

```js
const m = /(\d+(?:\.\d+)?)px/.exec(String(font));
const fs = m ? parseFloat(m[1]) : 16;
```

**한 줄짜리는 멀쩡하고 두 줄짜리만 사라지는 식으로 나타난다** — 한 줄은 크기를
안 쓰고 그리기 때문이다. 실제로 딥러닝 시뮬레이터에서 노드 값과 꼬리표가
그렇게 안 보였다(2026-08-22). **간선 라벨은 «글자는 보이는데 흰 받침만 없는»**
어중간한 모습이라 더 알아채기 어려웠다.

**찾는 법 — `fillText`를 가로채 그린 글자를 전부 모은다.** 좌표를 다시 계산하지
않으므로 실제로 그려진 것과 어긋날 수 없고, 겹침·화면 밖·원 밖을 한 번에 볼 수 있다.

## SVG 글자가 작다고 나올 때

`npm run check -- html`이 「SVG font-size 14 → 375px에서 약 13.0px」로 잡는 경우.

**계산은 이렇다.** 그리는 폭 ÷ viewBox 폭이 배율이고, 여기에 `font-size`를 곱한 값이
화면에 앉는 크기다. 그리는 폭은 `min-width`(자신 또는 조상)와 `max-width`가 정한다.
그래서 **`min-width`와 `max-width`가 같은 값이면 어느 화면에서나 같은 크기**다 —
좁은 화면만의 문제가 아니라 빔프로젝터에서도 그대로 작다.

```
필요한 min-width = viewBox 폭 × 16 ÷ 그 SVG에서 가장 작은 font-size
```

**`font-size`를 올리지 말고 그리는 폭을 올린다.** SVG 텍스트는 줄바꿈이 없어서
글자만 키우면 고정 크기 `<rect>`를 뚫는데, 브라우저로 재기 전에는 드러나지 않는다.
폭을 키우면 도형과 글자가 같은 비율로 커지므로 배치가 깨질 수 없다.

절차:

1. **`overflow-x-auto` 안인지 먼저 본다.** 아니면 `min-width`를 올리는 순간
   375px에서 페이지가 가로로 넘친다. 래퍼부터 씌운다.
2. 위 식으로 필요한 값을 구해 `min-width`를 올린다.
3. **인라인 `max-width`가 그보다 작으면 함께 올린다.** CSS는 `min-width`가 이기므로
   놔두면 죽은 값이 되어 읽는 사람을 헷갈리게 한다.
4. `npm run check -- html <파일>` — 「확인 필요」까지 0이 되어야 끝이다.

**가장 작은 `font-size`를 찾을 때 `<text>`만 보면 안 된다.** `<g font-size="14">`처럼
그룹에 붙어 상속되는 것이 있다.

## 메모리 도해를 새로 그릴 때

C 문법 강의노트에 도해를 넣으며 자리 잡은 규격이다(2026-08-22).
**폭을 정하는 계산을 그림마다 다시 하지 않으려고 값을 하나로 고정했다.**

```html
<div class="overflow-x-auto">
    <svg viewBox="0 0 576 <높이>" class="w-full h-auto max-w-xl mx-auto"
         style="min-width:576px" role="img" aria-label="...">
```

- `max-w-xl`이 576px이라 **바닥과 천장이 같은 값**이 된다 &rarr; 어느 화면에서나 배율 1.0.
- 그래서 **`font-size`에 적은 수가 화면에 앉는 픽셀 수와 같다.** 16 이상만 쓰면 검사가 조용하다.
- `min-width`가 `RENDER_W`를 넘으므로 **`overflow-x-auto` 래퍼가 반드시 필요하다.**
- 높이는 **마지막 글자의 baseline보다 10px 이상** 크게 잡는다. 같으면 아래가 잘린다.

**375px에서 도해는 래퍼 안에서 가로로 스크롤된다.** `section-card` 안에 두면 보이는 폭이
246px다(2026-08-22 실측) &mdash; 빔프로젝터에서는 온전히 보이지만 폰에서는 절반이 안 보인다.
그게 곤란하면 도해를 카드 밖으로 뺀다.

### 띄우지 않고 기하로 검증한다

브라우저는 사용자가 지시할 때만 쓴다. 그 전에 **좌표만으로 잡히는 결함**이 넷 있다.

| 보는 것 | 잡히는 결함 |
|---|---|
| 글자 폭 (한글 1.0em, 그 밖 0.55em으로 어림) | 캡션이 오른쪽으로 넘친다 |
| 마지막 baseline vs viewBox 높이 | 아래 글자가 잘린다 |
| `marker-end`가 달린 선·경로의 **끝점이 어떤 `<rect>`에도 닿지 않는가** | **화살표가 엉뚱한 곳을 가리킨다** |
| baseline 차 12px 미만 + 가로 구간 겹침 | 글자끼리 포갠다 |

셋째가 특히 값을 한다. 2026-08-22에 **화살표가 4번 칸 대신 0번 칸으로 내리꽂히던 것**을
이걸로 찾았다 &mdash; 눈으로 보지 않으면 못 찾을 종류였다.

**검증기가 시끄러우면 검증기부터 의심한다.** 처음 돌렸을 때 13건이 나왔는데 9건이 오탐이었다.
`text-anchor`를 속성 순서 때문에 못 잡아 **가운데 정렬을 왼쪽 정렬로 계산**하고 있었다 &mdash;
[사례집 1-15](강의노트-작성-사례집.md)와 같은 교훈이다.

### 글자만 보면 「찌부러짐」을 놓친다 — 도형까지 본다

위의 넷은 **글자**만 본다. 그래서 **도형이 겹치거나 캔버스를 벗어난 것**은 그대로 지나간다.
2026-08-22에 도형까지 보는 검사를 더해 파이썬 도해에서 넷을 잡았다.

| 보는 것 | 잡히는 결함 |
|---|---|
| 도형의 상자가 viewBox 안인가 | **오른쪽 끝이 잘린다** (인스턴스 상자가 2px 넘쳤다) |
| 사각형끼리 «걸치는가» &mdash; 한쪽이 다른 쪽을 온전히 품는 «중첩»은 정상 | 배지가 칸 모서리를 문다 |
| 글자가 «어느 상자에도 온전히 들지 않은 채» 상자와 겹치는가 | 캡션이 테두리를 관통한다 |

**브라우저를 띄울 수 있으면 `getBBox()`가 가장 확실하다.** 실제로 그려진 글자 폭까지
반영한 내용 상자를 돌려주므로, 어림한 글자 폭으로 판정하지 않아도 된다.

**어림으로 세면 오탐이 열 배가 된다.** 2026-08-22에 어림으로 저장소를 살폈을 때 38건이
나왔는데, `getBBox()`로 다시 재니 **283개 도해 가운데 4종만 남았다.** 한글을 1.0em으로
어림하는 것이 실제 글꼴보다 넓어서 「상자를 문다」가 무더기로 나온 것이다.
**띄울 수 있으면 어림하지 말고 브라우저에 묻는다.**

한 번에 모두 살피려면 `iframe`에 파일을 차례로 물려 재면 된다. `getBBox()`는 viewBox 좌표계라
**띄우는 폭과 무관**하므로, 375px로 맞추지 않아도 결과가 같다.

**「일부러 넘긴 것」은 주석으로 못박아 둔다.** 데이터과학 1-2-1의 강아지는 메신저 화면 안의
사진이라 아래가 잘린 것이 정상이다. 검사가 잡을 때마다 고쳐지지 않도록 그 자리에 적어 두었다.

```javascript
[...document.querySelectorAll('svg[style*="min-width"]')].map(s => {
    const p = s.getAttribute('viewBox').split(' ').map(Number), b = s.getBBox();
    return (b.x < -1 || b.y < -1 || b.x + b.width > p[2] + 1 || b.y + b.height > p[3] + 1)
        ? '넘침' : 'ok';
})
```

**속성을 정규식으로 읽을 때는 낱말 경계를 요구한다.** `x="([\d.]+)"`는 **`rx="12"` 안의
`x=`를 문다.** 속성을 알파벳 순으로 적은 도해(`fill height rx width x y`)가 통째로
오탐이 되어, 배경 사각형이 「viewBox 밖」으로 잡혔다. `x="…"`로 고친다.

## 나란히 놓는 짝을 그릴 때

2열 칸(`lg:grid-cols-2`) 안에 576짜리를 넣으면 **데스크톱에서도 가로로 밀린다** &mdash;
1280px 화면에서 카드 반쪽은 500px 남짓이라 576이 안 들어간다.

```html
<div class="overflow-x-auto">
    <svg viewBox="0 0 480 <높이>" class="w-full h-auto mx-auto"
         style="min-width:480px;max-width:480px" role="img" aria-label="...">
```

`checks/html.mjs`가 `max-width`를 천장으로, 조상의 `min-width`를 바닥으로 잡으므로
**둘을 같은 값으로 묶으면 어느 폭에서나 배율이 1**이다. 좁은 화면에서는 래퍼가 스크롤된다.

**칸을 나누는 것 말고 두 길이 더 있다.** 어느 쪽이 나은지는 그림이 정한다.
- **한 그림에 위아래로 합친다** &mdash; 같은 축으로 견주게 되어 오히려 낫다.
  사물 인터넷 도입부의 두 흐름이 이렇게 갔다.
- **세로로 쌓는다** &mdash; 옆의 카드가 그림에 딸린 설명이면 그림을 위로 올린다.

## 도식에 이름이 빠졌는지 알아보는 법

**밖에 붙은 「위치 해독표」를 찾는다.** 그림 안에 이름이 없으면 글쓴이는 자리로 짚어 줄
수밖에 없다. 이 문장들이 곧 결함의 표시다.

```
왼쪽 원본 데이터 · 가운데 압축된 데이터 · 오른쪽 되돌린 데이터
Q1 … (분홍 상자의 왼쪽 변)     보내는 쪽의 초록 동그라미 — 공개 키
```

찾는 법은 「`</svg>` 뒤 700자에 **방향말·색말 + 도형말**이 붙어 있는가」다.
`왼쪽|오른쪽|가운데|양 끝|첫째 칸` · `파란|붉은|초록|노란` &times;
`상자|동그라미|칸|막대|점선`. 2026-08-22에 이 방법으로 글자 없는 도해 120개에서
손댈 것 19개를 골라냈다.

**차트 예시는 걸려도 결함이 아니다.** 「가로축: 20대 · 30대」는 축 이름이지 해독표가 아니다.
가르는 기준은 **「상자가 여럿이고 각자 다른 뜻인가」**다.

## 캔버스가 흐리거나 옛 크기로 굳을 때

`<canvas>`는 **그리는 격자(`width`·`height` 속성)와 화면에 차지하는 크기(CSS)가 따로 논다.**
둘이 어긋나면 브라우저가 그림을 늘려서 얹으므로, 증상이 둘 중 하나로 나온다.

- **흐릿하다** — 격자가 화면보다 작다. 화면 배율(`devicePixelRatio`)을 안 곱한 것이다.
- **가로로 늘어지거나 눌린다** — 격자의 가로세로 비가 화면과 다르다. 잰 뒤에 상자가 바뀌었다.

**직접 재지 말고 `window.fitCanvas(canvas, ctx)`를 부른다**
([`src/entries/_lib/canvas-dpr.js`](../src/entries/_lib/canvas-dpr.js)).
돌려주는 `{w, h}`는 CSS 픽셀이고, **그리는 쪽은 그 값만 쓴다** —
`canvas.width`를 그대로 쓰면 배율이 곱해진 값이라 자리 계산이 어긋난다.
찍은 점을 캔버스 좌표로 들고 있는 페이지는 `fitCanvasFixed`로 좌표계를 붙들어 둔다.

밟기 쉬운 함정은 그 파일 머리말에 적어 두었다. 여기에는 **증상에서 되짚는 순서**만 적는다.

1. **`npm run check -- sim pages`를 먼저 돌린다.** 격자와 화면과 배율이 서로 맞는지 캔버스를 쓰는 페이지를 모두 살핀다.
   전체 화면을 드나든 뒤까지 본다.
2. 검사가 통과하는데 실제로 흐리면, **재는 시점**을 본다. 진입점은 `defer`라
   body 끝 인라인 스크립트보다 늦게 도므로, 파싱 시점에 `window.fitCanvas`를 부르면 없다.
   `DOMContentLoaded`로 미룬다(`load`는 글꼴을 기다려 너무 늦다).
3. **상자가 나중에 바뀌는 자리인지 본다.** 숨어 있던 탭이 드러나면 크기가 0에서 실제 값이
   되는데 창 크기는 그대로라 `resize`가 오지 않는다. `fitCanvas`가 `ResizeObserver`로
   상자를 지켜보다 `resize`를 한 번 쏘아 주므로 대개 여기서 끝난다.

**미리보기 도구의 `devicePixelRatio`를 근거로 삼지 않는다.** `javascript_tool`로 들여다볼 때만
1.25로 읽히고 페이지가 실제로 뜰 때는 1인 경우가 있었다(2026-08-21). 값이 이상하면
**페이지 안에서 `console.log`로 찍어** 로드 시점의 값을 본다.

## 오프라인 zip에서 그래프·트리·차트가 안 그려질 때

증상은 콘솔에 둘이 나란히 찍히는 것이다 — `blocked by CORS policy`와 `vis is not defined`.

**원인은 모듈 스크립트다.** `<script type="module">`은 CORS를 타는데 `file://`의 출처는
`null`이라 브라우저가 무조건 거절한다. 라이브러리를 window에 얹는 진입점이 실행되지 못하니
인라인 스크립트가 전역을 못 찾고 죽는다. **사이트에서는 멀쩡하므로 눈으로는 못 잡는다.**

지금은 빌드가 페이지마다 청크를 평범한 `<script defer>` 하나로 눌러 담는다
([`tools/vite/classic-scripts.js`](../tools/vite/classic-scripts.js)).
모듈이 다시 새어 나가는지는 `npm run check -- dist`가 지킨다 — **직접 세지 말고 이것을 돌린다.**

그래서 새 라이브러리를 넣었을 때 볼 것은 셋이다.

1. `npm run ci` — 산출물에 모듈이 남았거나 스크립트가 없는 파일을 가리키면 여기서 선다.
2. **빌드가 「Missing export」로 서면** rolldown이 CommonJS를 품은 공통 청크를
   `export` 문 없이 구운 것이다(1.2.3·1.2.4에서 확인). `classic-scripts.js`가 되살려 주는데,
   청크 모양이 달라지면 거기서 오류를 내며 선다. **위쪽이 고쳐졌으면 그 되살리기를 지운다.**
3. 페이지를 실제로 `file://`로 열어 본다. 스크립트가 실린 것과 그려지는 것은 다른 문제다.

## 강의노트를 한 과목씩 감사할 때

**통독은 비싸지 않다.** `npm run prose`가 HTML에서 본문만 뽑아 내는데, 2026-09-10에
재 보니 **원본의 6분의 1**이었다. 중단원 하나(강의노트 다섯 편)가 3만 토큰 안쪽이다.
**비싼 것은 읽기가 아니라 «같은 지적을 마흔 번 손으로 쓰는 것»이다.**

### 순서 — 검사가 먼저다

```
0. 그 과목에 걸리는 규칙을 «검사»로 먼저 만든다
1. 어휘를 한 번에 판정한다     npm run audit -- lemma "<과목>/*.html"
2. 서술을 중단원 묶음으로 돈다  npm run prose -- "<과목>/1-1-*.html" -o <임시>/unit.md
3. 파일 «사이» 대조를 마지막에 한 번
```

**0번을 건너뛰면 3번에서 같은 지적이 반복된다.** 2026-09-10 감사에서 확정 지적 넷 가운데
셋이 **「규칙은 `CLAUDE.md`에 있는데 검사가 없어서」** 생긴 것이었다. 뒤 차시 예고는 다섯
과목 모두에 쌓여 있었다 — **사람이 기억으로 지키던 자리는 예외 없이 샌다.**
검사를 먼저 세우면 그 유형은 서술을 볼 때 아예 안 나온다.

**1번이 2번보다 앞인 까닭**은 어휘 판정이 한 번에 끝나기 때문이다. 과목 하나의 용언은
표제어로는 수백 개라 **한 화면에서 전수로 본다.** 먼저 정리해 두면 중단원을 돌다가
낱말 문제로 멈추지 않는다.

**3번이 마지막인 까닭**은 「오개념을 심지 않는 서술」의 4·6·7번 — 같은 개념을 두 파일에서
다르게 말하는 것, 이어 붙인 예시 데이터의 값, 앞이 조건부로 세운 것을 뒤가 무조건으로
되돌리는 것 — 이 **한 파일만 봐서는 원리적으로 안 잡히기** 때문이다. 정의문 · 예시 표의
값 · 단정문만 뽑아 과목 단위 대조표를 만든다.

### 중단원 한 판의 되풀이

`npm run check -- prose <그 파일들>`로 **이미 물러난 말부터 걷어내고** → 추출본을 읽고 →
**지적을 「확정」과 「판단 필요」로 갈라** 적고 → 확정만 고치고 →
**다시 추출해 처음부터 통독한다** → `npm run check -- html <그 파일들>` → 중단원 단위로 커밋 →
사용자 확인 → 그 파일들을 `checks/prose.mjs`의 `DONE`에 올린다 → 다음.

**고친 뒤의 통독을 건너뛰지 않는다.** 2026-09-24 데이터과학 1-1·1-2에서 grep으로 찾아
한 줄씩 고치고 끝냈다가, 다시 읽으니 정의가 머리말과 어긋나 있었고, 「위 2번 문제」가 조건이
적힌 3번을 가리키고 있었으며, 핵심 정리 카드가 본문보다 단정했다. **줄 단위 수정은 문장 사이를
보지 못한다.** 새로 물러난 말은 그 자리에서 `checks/prose.mjs`에 올린다.

**「판단 필요」는 고치지 않고 채팅으로 올린다.** 2026-09-10에 그렇게 올린 덕분에
131곳짜리 일괄 치환을 하지 않았다 — 물어보니 갈래가 셋이었다.

### 과목 하나를 에이전트에 맡길 때

2026-09-24~25 다섯 과목 정제에서 굳은 순서다.

1. **기계 검사부터 돌린다** — `npm run check -- prose "<과목>/*.html" html "<과목>/*.html"`. 걸린 것은 읽기 전에 걷어낸다.
2. **에이전트에게는 `npm run prose` 추출본만 넘긴다.** HTML을 통째로 읽히지 않는다 —
   고칠 자리는 Grep으로 찾고 그 줄 근처만 연다.
3. **에이전트는 한 번에 하나만 띄우고, 지시문에 「하위 에이전트 금지」를 적는다.**
   적지 않으면 제 일을 다시 쪼개 넘기고, 누가 어느 파일을 고쳤는지 흩어진다.
4. **묶음(중단원이나 대단원) 단위로 고치고 커밋한다.** 파일 이름을 골라 `git add`한다.
5. **과목이 끝나면 본문 평문 diff를 다른 모델로 감사한다.** 기준 커밋의 파일을 임시 폴더로
   꺼내 `npm run prose`로 뽑고, 현재 파일도 같은 명령으로 뽑아 두 추출본을 비교한다.
   마크업 diff는 클래스 변경에 묻혀 문장 변화가 안 보인다.
6. **그 감사에서 고친 반영분만 다시 감사한다.** 고친 자리에서 새 오류가 난다.
7. **SVG 안 글자는 평문 diff에 없다** — 추출본이 SVG를 `aria-label`만 남기고 버리기
   때문이다. 도해 라벨을 고쳤으면 그 `<svg>`를 따로 연다.

### 함정 셋

- **낱말 교체는 파일 단위로 전부 아니면 전무다.** 절 제목 · nav · 학습 목표 · 짝을 이루는
  이름이 본문과 같은 낱말을 쓰면 **본문만 바꿀 수 없다.** 시험 삼아 세 파일만 고쳤다가
  본문과 퀴즈가 어긋나는 것을 보고 되돌렸다. 손대기 전에 **그 낱말이 이름 자리에도
  있는지부터 센다.**
- **활용형을 빠뜨리면 조용히 샌다.** 한국어 동사는 어미가 어간의 마지막 음절과 한 글자로
  합쳐져(`재` + `더` → **재던**) 어간 접두로는 못 찾는다. 금지어 정규식을 넓힐 때는
  `-ㄹ`/`-ㅂ` 꼴부터 적고, **넓힌 뒤 오탐이 0인지 확인한다.**
- **스크립트를 heredoc으로 넘기지 않는다.** 이 환경은 따옴표를 쳐도 백슬래시와 백틱을
  먹는다 — 정규식이나 백틱이 든 것은 파일로 쓴 뒤 돌린다.

### 감사에서 나온 판단은 검사로 굳힌다

**이것이 이 절차의 핵심이다.** 갈아 끼우기로 정한 낱말은 `checks/html.mjs`의
`BANNED_WORDS`나 `checks/verbs.mjs`의 목록에 넣고, 새로 세운 규칙은 `CLAUDE.md`에 적고
검사를 붙인다. **안 그러면 다음에 쓰는 파일에서 도로 새어 나온다.**
