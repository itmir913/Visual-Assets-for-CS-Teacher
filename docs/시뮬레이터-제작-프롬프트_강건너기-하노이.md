## 절대 규칙 (어기면 반려)

- **최소 글자 크기는 `text-base`.** `text-sm`, `text-xs`, `text-[13px]` 등 금지.
  SVG `font-size` 도 16 미만 금지. 교실 뒷자리·빔프로젝터 기준이다.
- **모든 `<table>` 은 `overflow-x-auto` 컨테이너로 감싸고 `min-w-[Npx]` 를 준다.**
  래퍼만 있고 min-width 가 없으면 375px 에서 열마다 줄바꿈되어 찌그러진다. 열당 120px 기준.
- **375px 폭에서 `document.documentElement.scrollWidth - clientWidth == 0`** 이어야 한다.
  넓은 요소는 전부 `overflow-x-auto` 컨테이너 **안**에 있어야 한다.
- **CDN 의존은 의도된 설계다.** 로컬 번들링·오프라인 대응을 제안하지 말 것. 단일 HTML 자체 완결.
- **터치 지원**: 클릭 조작 요소는 `pointerdown`/`pointerup` 으로 바인딩하고,
  드래그를 쓴다면 컨테이너에 `touch-action: none;` 을 주고 첫 요소의 포인터 캡처를 해제한다
  (CLAUDE.md 「터치 드래그 지원」 레시피 참조). 터치 타깃은 최소 44×44px.
- **커밋 메시지에 AI 협업 표시 문구 금지.** `Co-Authored-By`, `Generated with`, 🤖 등 일체 금지.

## 파일 1. 강 건너기 (`search-river-crossing.html`)

### 문제
농부가 늑대·양·양배추를 데리고 강을 건넌다. 배에는 농부와 한 가지만 탄다.
농부가 없는 쪽에 (늑대, 양) 이 남으면 늑대가 양을 먹고, (양, 양배추) 가 남으면 양이 양배추를 먹는다.

### 모델 (강의노트 1-2-1 과 표기를 반드시 일치시킬 것)
- 상태: `(농부, 늑대, 양, 양배추)` 각각 `왼` 또는 `오`
- 초기 상태 `(왼, 왼, 왼, 왼)`, 목표 상태 `(오, 오, 오, 오)`
- 연산자: 농부가 **혼자 / 늑대와 / 양과 / 양배추와** 반대편으로 건넌다 (최대 4가지).
  데려갈 대상은 농부와 같은 쪽에 있어야 한다.
- 전체 상태 2^4 = 16개, 그중 **규칙을 어기지 않는 유효 상태는 10개**
- 최소 해는 **7번 건너기**. 정답 순서:
  ① 양과 함께 → ② 혼자 돌아옴 ← ③ 늑대와 함께 → ④ 양을 데리고 돌아옴 ←
  ⑤ 양배추와 함께 → ⑥ 혼자 돌아옴 ← ⑦ 양과 함께 →

### 시뮬레이터 기능
1. **직접 풀기**: 강 좌우 두 강가와 배를 그림(SVG 또는 div)으로 표시. 왼쪽/오른쪽의 대상을 탭하면
   배에 태우고, [건너기] 버튼으로 이동. 규칙 위반이면 그 즉시 이유를 토스트로 알리고 되돌린다.
   건넌 횟수를 표시하고, 7번 이내에 성공하면 축하 메시지.
2. **AI 자동 풀이**: BFS 로 최단 해(7수)를 찾아 한 수씩 애니메이션으로 재생.
   [한 단계] / [자동 재생] / [처음부터] 버튼 제공.
3. **상태 공간 트리 보기**: 탐색하면서 만들어지는 트리를 표시.
   각 노드는 `(왼, 왼, 오, 왼)` 형태로 라벨을 달고, 규칙 위반 노드는 붉게 표시하며
   "가지치기됨" 이라고 명시한다. 이미 방문한 상태는 다시 펼치지 않는다는 것을 눈에 보이게 할 것.
4. `#summary` 절에 파이썬 의사코드(BFS)를 Prism 하이라이트로 싣고,
   상태를 튜플로 표현하는 부분을 강조 설명한다.
5. `#misconception` 절 주제: **"목표에서 멀어지는 이동은 손해 아닌가?"**
   → 4번째 수에서 양을 다시 데려오는 것이 정답 경로에 반드시 필요하다는 점을 다룬다.

## 파일 2. 하노이의 탑 (`search-tower-of-hanoi.html`)

### 문제
기둥 3개(A 출발, B 보조, C 목표), 크기가 다른 원판 n개. 한 번에 맨 위 원판 하나만 옮기고,
큰 원판을 작은 원판 위에 올릴 수 없다. 모두 A → C 로 옮기면 성공.

### 모델 (강의노트 1-2-1 과 표기를 반드시 일치시킬 것)
- 상태: 작은 원판부터 어느 기둥에 있는지. `(A, A, A)` 형태
- 초기 `(A, A, A)`, 목표 `(C, C, C)`
- 연산자: 한 기둥의 맨 위 원판을 다른 기둥의 맨 위로. 대부분의 상태에서 3가지,
  시작·완성 상태에서는 2가지
- 상태 공간 크기 **3^n** (n=3이면 27), 최소 이동 횟수 **2^n − 1** (n=3이면 7)

### 시뮬레이터 기능
1. **직접 풀기**: 원판 개수를 3~6개로 선택. 기둥을 탭해서 집고 놓는 방식
   (드래그가 아니라 **탭-탭** 방식이 태블릿에서 안정적이다). 규칙 위반이면 토스트로 이유 안내.
   현재 이동 횟수와 최소 이동 횟수 `2^n − 1` 을 나란히 표시한다.
2. **AI 자동 풀이**: 재귀 해법으로 최적 수열을 만들어 한 수씩 애니메이션 재생.
   [한 단계] / [자동 재생] / [속도 조절] / [처음부터].
3. **상태 공간 보기**: n=3 일 때 27개 상태를 노드로 하는 그래프를 그리고
   (정삼각형 배치, 이른바 시에르핀스키 삼각형 모양) 최적 경로 7수를 강조 표시한다.
   n>3 이면 이 절은 "상태가 너무 많아 그리지 않는다"고 안내하고 개수만 보여 준다.
4. `#summary` 절에 재귀 의사코드를 싣고, **연산자에 조건(전제)이 붙는다**는 점을 강조한다.
5. `#misconception` 절 주제: **"원판이 하나 늘면 조금 어려워지는 정도 아닌가?"**
   → 상태 수 3^n, 최소 이동 2^n − 1 이 얼마나 빨리 커지는지 표로 보여 준다
   (n = 3, 5, 10, 20 정도).

## 검증 (커밋 전 필수)

로컬 정적 서버를 띄우고(`python -m http.server 8777`) 브라우저로 연 뒤 확인한다.
`file://` URL 은 프리뷰에 안 실리므로 반드시 서버를 쓴다.

- [ ] 콘솔 에러 0
- [ ] 375px 에서 `documentElement.scrollWidth - clientWidth == 0`
      (iframe `scrollLeft` 로 재면 부정확하다. 반드시 이 식으로 확인)
- [ ] 16px 미만 텍스트 0 (`getComputedStyle(el).fontSize` 로 전수 확인, SVG text 포함)
- [ ] 모든 표가 `overflow-x-auto` + `min-w-[Npx]` 안에 있는지
- [ ] 자동 풀이가 강 건너기 7수 / 하노이 2^n − 1 수로 끝나는지 실제로 실행해 확인
- [ ] 빈 상태·연타·자동 재생 중 리셋 등 경계 케이스에서 무한 루프나 멈춤이 없는지
