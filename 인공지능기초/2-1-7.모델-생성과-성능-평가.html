인공지능으로 어떤 문제를 해결할까?

문제의 특성에 따라 인공지능이 알맞은 해결 방법인지 따져 봅시다.

핵심 개념

인공지능은 인식이나 추론, 학습 같은 방법으로 문제를 해결하기에 적합하다. 따라서 모든 문제에 인공지능을 적용하는 것이 좋은 것은 아니며, 문제의 특성에 따라 적합한 해결 방법을 선택해야 한다.

전통적인 문제 해결

  • 수식이나 규칙으로 표현 가능
  • 데이터가 달라져도 해결 방법이 변하지 않음
  • 알고리즘이 명확히 존재

예시

불꽃지수 계산 놀이공원 입장료 랜덤 발표 순서

인공지능을 적용한 문제 해결

  • 데이터가 많고 규칙이 계속 달라짐
  • 인식·추론·학습이 필요한 문제
  • 수많은 데이터에서 패턴을 자동으로 찾음

예시

기계학습으로 어떻게 문제를 해결할 수 있을까?

문제 정의부터 모델 활용까지 이어지는 다섯 단계를 살펴봅시다.

기계학습 모델 구현 과정은 문제 정의에서 모델 활용까지의 5단계로 구성된다. 이 단계는 반드시 순서대로 한 번만 진행하는 것이 아니라, 필요에 따라 이전 단계로 돌아가 수정할 수 있다.

1

문제 정의

해결하고자 하는 문제가 인공지능으로 해결 가능한지 확인하고, 문제를 명확히 정의한다. 필요한 데이터가 무엇인지, 그것을 확보할 수 있는지 검토해야 한다.

분류 문제인지, 회귀 문제인지 결정 입력·출력 데이터 형태 파악
2

데이터 수집

정의된 문제에 적합한 대표성 있는 데이터를 수집한다. 데이터의 규모·형태·수집 방법을 고려하며, 수집한 데이터는 훈련 데이터와 테스트 데이터로 분리한다.

훈련 데이터 — 모델 학습에 사용
테스트 데이터 — 성능 평가에 사용

훈련 데이터와 테스트 데이터를 왜 나눌까?

모델이 훈련 데이터에만 과도하게 적응하면, 그 데이터에서는 잘 맞지만 새로운 데이터에서는 예측을 잘못하는 과적합(overfitting)이 발생할 수 있다. 훈련에 사용하지 않은 테스트 데이터로 성능을 확인해야 모델이 일반화(generalization) 능력을 갖췄는지 올바르게 평가할 수 있다. 일반적으로 전체 데이터를 훈련 데이터 7 : 테스트 데이터 3 (또는 8:2) 비율로 나눈다.

3

데이터 탐색

수집한 데이터의 핵심 속성을 파악한다. 수치 데이터는 이상치 여부를 확인하고, 이미지·텍스트 데이터는 전처리 방법을 결정한다.

정형 데이터 — 수치 이상치 확인, 결측치 처리
비정형 데이터(텍스트) — 코퍼스 구성, 전처리, 단어 모음 생성
4

모델링 및 성능 평가

훈련 데이터를 입력하여 기계학습 모델을 학습시키고, 테스트 데이터로 성능을 평가하여 적합한 모델을 선택한다.

과대적합 (Overfitting)

훈련 데이터에만 지나치게 최적화되어 새로운 데이터에 성능이 낮아지는 상태

→ 훈련 데이터 수 늘리기, 모델 복잡도 줄이기

과소적합 (Underfitting)

모델이 너무 단순하여 훈련 데이터에서도 좋은 성능을 보이지 못하는 상태

→ 더 복잡한 모델 선택, 충분히 학습시키기

두 상태는 훈련 데이터 성적과 새 데이터 성적을 나란히 놓아야 구별된다. 훈련 데이터 성적만 보고 있으면 과대적합은 오히려 성적이 좋은 것처럼 보인다. 그래서 훈련에 쓰지 않은 데이터를 따로 남겨 두는 것이다.

5

모델 활용

모델링 및 성능 평가를 마치고 선택한 모델에 새로운 데이터를 입력하여 예측·분류 결과를 확인한다. 실제 인공지능 제품에 적용해 보는 단계이다.

훈련 데이터 (Training Data)

모델의 학습에 사용하는 데이터. 기계학습 모델은 훈련 데이터에서 패턴을 찾아 학습한다.

테스트 데이터 (Test Data)

학습을 마친 모델의 성능을 평가하기 위해 사용하는 데이터. 훈련에 사용하지 않은 새로운 데이터이다.

외운 것을 그대로 물어보면 잘하는 것이 당연하다는 데서 출발합니다.

외운 문제를 다시 내면 점수는 언제나 높다

학생 A가 문제집을 통째로 외웠다고 하자. 그 문제집에서 그대로 낸 시험은 만점이 나올 것이다. 하지만 우리가 알고 싶은 것은 문제집을 얼마나 외웠는가가 아니라 처음 보는 문제도 풀 수 있는가이다. 모델도 똑같다. 학습에 쓴 데이터로 성적을 측정하면 그 성적은 실력과 암기를 구별해 주지 못한다.

일반화(generalization)

학습에 쓴 데이터뿐 아니라 학습할 때 본 적 없는 데이터에서도 제 역할을 하는 성질이다. 기계학습에서 「성능이 좋다」는 말은 대개 이 성질을 가리킨다. 그래서 성능은 훈련에 쓰지 않고 남겨 둔 데이터로만 측정한다.

그런데 테스트 데이터도 닳는다

모델을 한 번 만들고 끝내는 경우는 거의 없다. 설정값을 조금씩 바꿔 가며 여러 번 만들어 보고, 그때마다 테스트 데이터로 점수를 측정해 더 나은 쪽을 고르게 된다. 문제는 「더 나은 쪽을 고르는 일」 자체가 이미 학습이라는 점이다. 테스트 데이터의 점수를 보고 사람이 설정을 고쳤다면, 그 데이터의 정보는 이미 모델에 흘러 들어간 것이다.

테스트 데이터로 모델을 고르지 않는다

테스트 데이터를 여러 번 들여다보며 모델을 고르면, 그 데이터는 더 이상 「본 적 없는 데이터」가 아니다. 시험 문제를 미리 보고 공부한 뒤 그 시험으로 실력을 측정하는 셈이라, 점수는 실제보다 높게 나온다. 고르는 일에 쓸 데이터는 따로 마련하고, 테스트 데이터는 마지막 채점에 한 번만 쓴다.

전처리 기준값을 학습 데이터에서만 정했던 까닭도 같다

앞서 정규화·표준화를 배울 때, 기준으로 삼는 값(최솟값·최댓값, 평균·표준 편차)은 학습에 쓴 데이터에서 한 번만 정해 새 데이터에도 그대로 쓴다고 해 두었다. 그 까닭이 여기에 있다. 테스트 데이터까지 합쳐서 평균을 구하면, 테스트 데이터의 값이 이미 전처리 단계에서 모델에 반영되어 채점이 후해진다. 새 데이터가 한 건씩 들어오는 실제 상황에서는 애초에 평균을 다시 구할 수도 없다.

해결책 하나 — 검증 데이터를 따로 떼어 둔다 (홀드아웃 교차 검증)

훈련 데이터에서 일부를 다시 떼어 검증 데이터(validation data)로 삼는 방법이다. 설정을 바꿔 가며 성능을 비교하는 일은 검증 데이터로 하고, 이제 더 손대지 않겠다고 정한 다음에야 테스트 데이터로 마지막 점수를 낸다. 이렇게 한 번 갈라 두고 쓰는 방식을 홀드아웃 교차 검증이라고 한다.

한 번만 갈라 두므로 빠르지만, 어디를 잘라 검증 데이터로 삼았느냐에 따라 점수가 흔들린다. 특히 데이터가 적을수록 흔들림이 크다.

해결책 둘 — 자리를 바꿔 가며 여러 번 측정한다 (k-폴드 교차 검증)

데이터를 k개의 덩어리(폴드, fold)로 나눈 뒤, 한 덩어리씩 돌아가며 검증에 쓰고 나머지로 학습하는 방법이다. k가 5면 이 과정을 다섯 번 반복하고, 다섯 번의 점수를 평균 내어 성능으로 삼는다. 어느 한 번의 갈라짐에 점수가 휘둘리지 않게 하려는 것이다.

방법 이럴 때 쓴다 함께 따라오는 조건
홀드아웃
교차 검증		 데이터가 넉넉하고, 성능을 빠르게 훑어보고 싶을 때 어디서 잘랐느냐에 따라 점수가 달라진다. 데이터가 적으면 흔들림이 크다
k-폴드
교차 검증		 데이터가 적거나, 점수를 좀 더 믿을 만하게 내고 싶을 때 학습을 k번 반복하므로 시간이 k배로 든다

둘 중 어느 쪽이 더 좋은 방법이라고 정해져 있지 않다. 오른쪽 칸이 곧 대가이므로, 데이터의 양과 쓸 수 있는 시간을 보고 고른다. 또 어느 쪽을 쓰든 테스트 데이터를 마지막까지 아껴 둔다는 원칙은 달라지지 않는다.

교차 검증 (Cross Validation)이란?

Random sampling 대신 Cross validation을 고르면 k-폴드 교차 검증으로 성능을 측정한다. 데이터를 k등분해 한 덩어리씩 돌아가며 검증에 쓰고 나머지로 학습하는 과정을 k번 반복한 뒤, k번의 점수를 평균 내는 방식이다. 앞 절 「데이터를 왜 굳이 나누어 둘까?」에서 홀드아웃 교차 검증과 나란히 다루었다. 데이터가 80개뿐인 이 실습처럼 데이터가 적을 때 특히 도움이 된다.

AUC는 아직 다루지 않은 지표다. 스팸이라고 판정할 문턱을 이리저리 옮겨 가며 측정해 본 성적을 하나로 모은 값이라고만 알아 두자. 0.5면 찍은 것과 다를 바 없고 1에 가까울수록 좋다. 이름까지 외울 필요는 없다.

「정확도가 더 높으니 더 좋은 모델」이라고 잘라 말할 수는 없다. 위에서도 AUC는 로지스틱 회귀 쪽이 더 높다. 어느 지표를 앞에 둘지는 문제가 정한다 — 스팸을 한 통도 놓치고 싶지 않다면 재현율을, 중요한 메시지가 스팸함으로 가는 일을 막고 싶다면 정밀도를 먼저 본다. 게다가 이 점수들은 데이터 80개로 세 번 나눠 측정한 결과라, 데이터가 바뀌면 순서도 바뀔 수 있다.

그리고 이렇게 여러 모델을 비교해 하나를 고르는 일은 원래 검증 데이터가 맡는 일이다. 고른 뒤에 남겨 둔 테스트 데이터로 채점해야 그 점수를 믿을 수 있다.

분류 모델의 성능 평가

모델이 얼마나 잘 맞혔는지는 무엇을 보고 판단할까?

혼동 행렬에서 출발해 정확도·정밀도·재현율·특이도를 읽어 봅시다.

맞히려는 것이 무엇이냐에 따라 측정하는 방법도 달라진다. 분류는 갈래를 맞혔는지 틀렸는지 세고, 회귀는 값이 얼마나 빗나갔는지 재며, 군집은 정답이 없으므로 묶인 모양이 얼마나 그럴듯한지를 본다. 이 절에서는 분류를 먼저 보고, 회귀와 군집은 다음 절에서 이어 본다.

혼동 행렬 (Confusion Matrix)

기계학습 모델의 예측 오류가 얼마인지, 어떤 유형의 오류가 발생했는지를 한눈에 보여주는 표이다.

네 칸의 이름은 두 글자로 읽는다

  • 앞 글자 T/F — 모델의 판정이 실제와 맞았으면 T(True), 어긋났으면 F(False)
  • 뒤 글자 P/N — 모델이 양성이라 판정했으면 P(Positive), 음성이라 판정했으면 N(Negative)

여기서 양성(P)은 우리가 찾아내려는 쪽을 가리키는 이름일 뿐, 좋다는 뜻이 아니다. 스팸 분류라면 스팸이 양성이고, 불량품 판별이라면 불량이 양성이다. 무엇을 양성으로 두느냐를 먼저 정해야 아래 지표들이 말이 된다.

아래 수치는 지표의 계산 방법을 보여주기 위해 든 가상의 예시이며, 앞서 제시한 스팸 분류 모델의 실제 성능 수치와는 별개이다.

정확도만 보면 안 되는 까닭

숫자 하나로 모델을 판단할 때 생기는 함정을 봅시다.

정확도가 99%인데 쓸모없는 모델

어떤 희귀병이 1,000명 중 3명에게 나타난다고 하자. 「누가 와도 병이 아니라고 답하는」 모델을 만들어 보면 어떻게 될까. 1,000명 중 997명을 맞히므로 정확도는 99.7%다. 그런데 이 모델은 환자를 단 한 명도 찾아내지 못한다.

지표 이 모델의 값 무엇을 말하고 있나
정확도 997 / 1000 = 0.997 거의 다 맞힌 것처럼 보인다
재현율 0 / 3 = 0 실제 환자 세 명 중 아무도 찾지 못했다
정밀도 구할 수 없음 양성이라 판정한 적이 없어 나눗셈의 분모가 0이 된다

한쪽 갈래가 훨씬 많은 데이터를 불균형 데이터라고 한다. 이런 데이터에서는 정확도만 보아서는 안 된다. 많은 쪽으로만 답해도 값이 높게 나오기 때문이다. 그래서 정밀도·재현율·특이도가 따로 있는 것이고, 혼동 행렬의 네 칸을 직접 들여다보아야 하는 것이다. 거꾸로 두 갈래의 수가 비슷하다면 정확도는 여전히 읽기 쉽고 쓸모 있는 지표다.

정밀도와 재현율은 함께 올리기 어렵다

두 지표는 모두 TP(제대로 찾아낸 양성)를 늘리려 하지만, 줄이려는 실수가 서로 다르다. 정밀도는 FP를 줄이는 쪽이고 재현율은 FN을 줄이는 쪽이다. 의심스러우면 일단 양성이라 판정하도록 문턱을 낮추면 놓치는 것(FN)이 줄어 재현율은 오르지만, 애먼 것까지 양성이라 하게 되어(FP) 정밀도는 떨어진다. 문턱을 높이면 반대가 된다. 한쪽을 올리면 다른 쪽이 내려가기 쉬운 사이라, 어느 실수가 더 아픈지를 보고 균형점을 정한다.

정밀도를 먼저 보는 경우 — 스팸 분류

스팸을 몇 통 놓치면 지우는 수고로 끝나지만, 합격 통보 메일이 스팸함으로 가면 되돌리기 어렵다. 정상을 스팸이라 하는 실수(FP)가 더 아프므로 정밀도를 먼저 본다.

재현율을 먼저 보는 경우 — 산불 감지

연기가 아닌 것을 연기라 해서 헛출동하면 인력과 비용이 들지만, 실제 산불을 놓치면 되돌릴 수 없다. 양성을 음성이라 하는 실수(FN)가 더 아프므로 재현율을 먼저 본다.

둘 중 하나가 더 중요한 지표라고 정해져 있지 않다. 같은 지표라도 문제가 바뀌면 순위가 뒤집힌다. 두 지표를 한 숫자로 함께 보고 싶을 때 F1-점수를 쓰지만, F1은 어느 쪽 실수가 더 아픈지를 대신 판단해 주지는 않는다.

회귀 — 얼마나 빗나갔는지를 측정한다

회귀는 연속적인 값을 맞히는 문제라 맞았다·틀렸다로 셀 수가 없다. 398건을 예측했는데 실제가 401건이라면 틀린 것이지만, 500건이라 예측한 경우와 같은 취급을 할 수는 없다. 그래서 회귀는 얼마나 빗나갔는지를 측정하고, 그 빗나간 양을 오차(error)라고 한다. 점이 여러 개면 오차도 여러 개이므로, 이를 하나의 숫자로 모아야 두 모델을 비교할 수 있다.

오차를 하나로 모으는 방식이 여러 가지라 이름도 여럿이다. 이산화탄소 배경 대기 농도 예측 실습에서 본 지표들이 그것이다.

지표 의미 좋은 모델의 조건
평균제곱오차
(MSE)		 예측값과 실제값 차이를 제곱하여 평균한 값 값이 0에 가까울수록 좋음
평균제곱근오차
(RMSE)		 MSE의 제곱근. 제곱하며 부풀었던 값을 되돌려, 원래 단위(ppm·건·분)로 읽을 수 있게 한 값 값이 작을수록 좋음
평균절대오차
(MAE)		 예측값과 실제값 차이의 절댓값을 평균한 값 값이 작을수록 좋음
결정 계수
(R²)		 맞히려는 값이 오르내리는 폭 가운데 모델이 설명해 낸 몫. 비율이라 단위가 없다 값이 1에 가까울수록 좋음
MSE·RMSE는 오차를 제곱하기 때문에 크게 빗나간 점 하나에 크게 흔들리고, MAE는 오차 크기를 그대로 더하므로 점들이 평균적으로 얼마나 빗나갔는지를 보여 준다. 어느 쪽이 옳은 지표라기보다, 크게 빗나가는 것을 특히 막아야 하는 문제라면 MSE·RMSE를, 전반을 고르게 보고 싶다면 MAE를 앞세운다.

결정 계수가 「언제나 0에서 1 사이」는 아니다

모델을 만들 때 쓴 데이터로 측정하면 0에서 1 사이가 나온다. 그런데 본 적 없는 데이터로 채점하면 0보다 작아질 수도 있다. 0은 「그냥 평균값으로 답하는 것과 다를 바 없다」는 뜻이고, 음수는 「평균으로 답하느니만 못하다」는 뜻이다. 테스트 데이터에서 결정 계수가 음수로 나왔다면 계산이 틀린 것이 아니라, 그 모델이 새 데이터에서 제 몫을 못 하고 있다는 신호다.

군집 — 정답이 없는데 무엇을 재나

군집화는 레이블(정답표) 없이 비슷한 것끼리 묶는 일이라, 맞았는지 비교해 볼 정답 자체가 없다. 그래서 묶인 모양을 본다. 잘 묶였다면 두 가지가 동시에 성립해야 한다 — 같은 덩어리 안의 것들은 서로 가깝고, 다른 덩어리와는 멀리 떨어져 있어야 한다.

a — 우리 편과의 거리

어떤 점에서 같은 군집에 있는 다른 점들까지의 평균 거리. 작을수록 좋다.

b — 가장 가까운 옆 동네와의 거리

그 점에서 가장 가까운 다른 군집의 점들까지의 평균 거리. 클수록 좋다.

실루엣 계수(silhouette coefficient)

(b − a) ÷ (a와 b 중 큰 값)

점 하나하나에게 「지금 있는 군집이 맞느냐」고 묻는 값이다. 큰 값으로 나누는 것은 결과를 −1에서 1 사이로 가두기 위해서다.

값 그 점이 어떤 상태인가
1에 가까움 우리 편은 가깝고 남은 멀다. 제자리에 잘 들어가 있다
0 근처 양쪽이 비슷하게 멀다. 두 군집의 경계에 걸쳐 있다
−1에 가까움 남이 우리 편보다 가깝다. 엉뚱한 군집에 들어가 있다

점 하나의 실루엣 계수가 높다고 전체 군집화가 잘된 것은 아니다. 보통은 모든 점의 값을 평균 내어 보고, 군집마다의 평균이 전체 평균에서 크게 벗어나지 않는지도 함께 살핀다. 군집을 몇 개로 나눌지(k)를 정할 때 참고하기도 한다. 다만 이 값은 데이터 안의 거리만 보고 만들어진 값이라, 나뉜 덩어리가 사람에게 쓸모 있는 구분인지까지 말해 주지는 못한다. 그 판단은 결국 사람의 몫이다.

Q. 기계학습 모델 구현 과정은 어떻게 구성될까?

A. 문제 정의 → 데이터 수집 → 데이터 탐색 → 모델링 및 성능 평가 → 모델 활용의 5단계로 구성된다. 각 단계는 반드시 순서대로 한 번에 끝내는 것이 아니라, 성능이 충분하지 않으면 이전 단계로 돌아가 수정할 수 있다. 훈련 데이터와 테스트 데이터를 나누는 것은 과적합을 막고 일반화 성능을 확인하기 위해서이다. 설정을 바꿔 가며 모델을 고르는 일은 검증 데이터로 하고, 테스트 데이터는 마지막 채점에 한 번만 쓴다.

핵심 용어

  • 훈련 데이터 — 모델 학습에 사용
  • 검증 데이터 — 설정을 바꿔 가며 모델을 고를 때 사용
  • 테스트 데이터 — 마지막 성능 평가에 한 번만 사용
  • 과적합 — 훈련 데이터에서는 잘하는데 새 데이터에서는 못함
  • 일반화 — 본 적 없는 데이터에서도 제 역할을 함

분류 성능 지표

  • 정확도(CA) — 전체 정답 비율. 갈래가 치우친 데이터에서는 이것만 보지 않음
  • 정밀도 — 양성 판정 중 실제 양성
  • 재현율 — 실제 양성 중 찾아낸 비율
  • 특이도 — 실제 음성 중 음성으로 맞힌 비율
  • F1-점수 — 정밀도·재현율 조화 평균. 어느 실수가 더 아픈지는 알려 주지 않음

회귀·군집 성능 지표

  • MSE·RMSE·MAE — 오차를 모은 값. 작을수록 좋음
  • 결정 계수(R²) — 클수록 좋음. 만들 때 쓴 데이터로 측정하면 0~1, 본 적 없는 데이터로 측정하면 음수도 가능
  • 실루엣 계수 — 군집용. −1~1, 클수록 제자리에 잘 들어간 것

오렌지 실습 흐름

  • 스팸 분류: Bag of Words → Neural Network → Test and Score → Predictions
  • CO₂ 예측: Linear Regression → Test and Score(k-fold) → 오차·결정 계수 확인
