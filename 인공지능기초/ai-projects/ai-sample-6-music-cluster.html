아이디어 발견부터 설계까지

이 모델은 어떤 계기로 만들게 됐을까? 왜 기계학습이 필요한지, 왜 하필 이 방법인지 사고의 흐름을 따라가 보자.

1

어디서 아이디어를 얻었나? — 실생활의 불편함

음악 스트리밍 앱의 추천이 자꾸 취향과 달라서 결국 직접 플레이리스트를 만들게 됐다. 그런데 취향이 비슷한 친구가 추천하는 곡은 거의 다 좋더라. '비슷한 취향의 사람들을 자동으로 묶을 수 있다면 훨씬 잘 맞는 음악을 추천받을 수 있지 않을까?' 하는 아이디어에서 출발했다.

2

왜 기계학습이 필요한가? — 전통적 코딩의 한계

"BPM 150 이상은 헬스 음악 팬으로 분류"처럼 규칙을 만들면 안 될까? 실제 음악 취향은 BPM뿐 아니라 에너지, 어쿠스틱 비율, 댄서빌리티 등 여러 요소의 조합으로 결정된다. 사람이 직접 기준을 정하는 것보다, 데이터에서 자연스럽게 유사한 패턴을 찾아주는 기계학습이 훨씬 정확하다.

3

왜 군집(K-평균)인가? — 기계학습 방법 선택의 논리

"헬스 팬", "공부 팬" 같은 취향 유형은 미리 정해진 정답이 없다. 몇 가지 유형이 존재하는지조차 사전에 알 수 없다. 정답 레이블 없이 데이터 자체의 유사성을 바탕으로 자동으로 묶는 비지도학습이 적합하고, 데이터를 K개의 그룹으로 나누는 K-평균 군집화가 이 문제에 잘 맞는다.

문항 1. 문제 정의

실생활에서 AI로 해결하고자 하는 문제를 구체적으로 정의하시오.

음악 스트리밍 서비스(멜론, 스포티파이 등)에는 수천만 곡이 있지만, 추천 알고리즘이 항상 취향에 맞는 곡을 추천해주지는 않는다. 사람마다 좋아하는 음악의 특성(빠르기, 에너지, 분위기 등)이 달라 단순히 '많이 들은 곡'을 기준으로 한 추천은 한계가 있다.

음악의 특성 데이터를 분석하여 비슷한 취향의 리스너를 군집으로 묶고, 군집별로 맞춤 플레이리스트를 추천하는 데 활용하고자 한다.

자기점검 체크리스트

  • ☑ 해결하고자 하는 문제가 실생활과 연관되어 구체적으로 제시되어 있다.
  • ☑ 문제가 발생하는 상황(불편함·필요성)이 명확하게 서술되어 있다.

문항 2. 모델 설명 (입력 → 출력)

어떤 데이터를 입력받아 어떤 결과를 출력하는지 서술하시오.

  • ■ 입력: 사용자가 주로 청취한 음악의 평균 특성 데이터 (BPM, 에너지, 어쿠스틱 비율, 가사 유무, 댄서빌리티)
  • ■ 출력: 취향 유형 군집 번호 + 군집별 특성 요약

레이블 없이 데이터만으로 비슷한 음악 취향을 가진 사람들을 자동으로 묶어, 각 군집이 어떤 유형의 리스너인지 특성을 요약한다.

  • • 군집 1 — 고에너지·고BPM 선호 (헬스·러닝 음악 팬)
  • • 군집 2 — 저BPM·어쿠스틱 선호 (공부·힐링 음악 팬)
  • • 군집 3 — 중간BPM·높은 댄서빌리티 (파티·클럽 음악 팬)

자기점검 체크리스트

  • ☑ 입력 데이터가 명확히 제시되어 있다.
  • ☑ 모델이 출력하는 결과가 구체적으로 서술되어 있다.
  • ☑ 입력과 출력을 통해 모델의 역할이 명확하게 드러난다.

문항 3. 기계학습 유형 및 구현 도구 선택

① 기계학습 유형, ② 구현 도구를 선택하고 각각 이유를 서술하시오.

① 기계학습 유형: 비지도학습 — 군집 (K-평균)

각 사용자에게 '헬스 음악 팬', '공부 음악 팬' 같은 레이블이 미리 없으므로 정답 없이 데이터의 유사성만으로 묶는 비지도학습이 적합하다. K-평균(K-Means) 알고리즘은 데이터를 K개의 군집으로 나누어 각 군집 내 데이터들이 서로 가장 유사하도록 군집 중심을 반복 조정한다.

② 구현 도구: Orange

Orange의 k-Means 노드와 Scatter Plot 노드를 연결하면 군집 결과를 색으로 구분한 2D 시각화로 바로 확인할 수 있다. Silhouette Score로 최적 K값을 결정할 수 있는 기능도 제공된다.

자기점검 체크리스트

  • ☑ 지도/비지도학습 중 하나를 명확히 선택하였다.
  • ☑ 유형 선택 이유가 논리적으로 서술되어 있다.
  • ☑ 구현 도구 선택 이유가 기계학습 유형과 연결되어 설명되어 있다.

문항 4. 데이터 설명

데이터의 출처·유형·수량·특성을 작성하고, 스크린샷을 첨부하시오.

  • • 출처: Spotify Web API + Kaggle 'Spotify Tracks Dataset' (공개 데이터)
  • • 유형: 수치형 정형 데이터 (CSV, 5개 특성)
  • • 수량: 200명의 사용자별 평균 청취 음악 특성 (200행)
BPM  | 에너지(0~1) | 어쿠스틱(0~1) | 가사유무(0/1) | 댄서빌리티(0~1)
─────┼────────────┼──────────────┼──────────────┼───────────────

※ 스크린샷: Spotify API 데이터 수집 화면 및 Orange CSV 로드 화면 [실제 수행평가 시 첨부]

자기점검 체크리스트

  • ☑ 데이터의 출처가 명시되어 있다.
  • ☑ 데이터의 유형과 수량이 구체적으로 서술되어 있다.
  • ☑ 학습에 사용된 데이터 화면 스크린샷이 첨부되어 있다.

문항 5. 학습 결과

학습 완료 화면을 스크린샷으로 첨부하고, 결과의 의미를 설명하시오.

• 최적 K값 결정: K를 2~5까지 바꿔가며 Orange Scatter Plot으로 군집 분리 결과를 직접 비교 → K=3일 때 군집이 가장 뚜렷하게 분리됨 → 3개 군집으로 결정

군집 결과 요약

  • • 군집 1 (54명) — 헬스·러닝 팬: 평균 BPM 162 / 에너지 0.89 / 어쿠스틱 0.05 / 댄서빌리티 0.71
  • • 군집 2 (78명) — 공부·힐링 팬: 평균 BPM 76 / 에너지 0.27 / 어쿠스틱 0.82 / 댄서빌리티 0.21
  • • 군집 3 (68명) — 파티·클럽 팬: 평균 BPM 121 / 에너지 0.68 / 어쿠스틱 0.18 / 댄서빌리티 0.86

Scatter Plot(BPM vs 에너지)에서 3개 군집이 색으로 뚜렷하게 분리됨

※ 스크린샷: Orange Scatter Plot 군집 시각화 화면 [실제 수행평가 시 첨부]

자기점검 체크리스트

  • ☑ 학습 완료 화면 또는 학습 결과 스크린샷이 첨부되어 있다.
  • ☑ 모델의 학습 결과를 확인할 수 있는 수치나 지표가 언급되어 있다.
  • ☑ 학습 결과의 의미가 서술되어 있다.

문항 6. 테스트 및 결과 분석

새로운 데이터로 테스트하고, 예상 결과와 실제 결과를 비교·분석하시오.

■ 테스트 1 — 헬스 음악 팬 예상 사용자

  • 입력: BPM 175 / 에너지 0.93 / 어쿠스틱 0.03 / 가사유무 1 / 댄서빌리티 0.78
  • 예상: 군집 1(헬스·러닝 팬)으로 분류
  • 실제 출력: 군집 1 배정 → 예상과 일치

■ 테스트 2 — 클래식·재즈 팬 예상 사용자

  • 입력: BPM 68 / 에너지 0.18 / 어쿠스틱 0.94 / 가사유무 0 / 댄서빌리티 0.10
  • 예상: 군집 2(공부·힐링 팬)로 분류
  • 실제 출력: 군집 2 배정 → 예상과 일치

■ 분석

BPM과 에너지 수치가 군집 분류에 가장 큰 영향을 미쳤다. 군집 간 경계에 있는 데이터(예: BPM 100, 에너지 0.50)는 군집 2와 3 사이에서 배정이 달라질 수 있어 경계 사례 처리가 필요하다.

자기점검 체크리스트

  • ☑ 학습에 사용하지 않은 새로운 데이터로 테스트를 수행하였다.
  • ☑ 예상 결과와 실제 결과가 모두 서술되어 있다.
  • ☑ 차이가 있다면 그 원인이 분석되어 있다.

문항 7. 기대 효과 및 개선 사항

모델 적용 시 기대 효과와 현재 모델의 한계 및 개선 방향을 서술하시오.

기대 효과

관심 분야: 엔터테인먼트 · 마케팅

음악 스트리밍 플랫폼에서 군집별로 맞춤 플레이리스트를 자동 생성하면 사용자 만족도와 앱 사용 시간을 높일 수 있다.

음원 광고에서도 군집별로 타깃 광고를 집행하여 마케팅 효율을 높이는 데 활용할 수 있다.

개선 사항

현재 모델의 한계: 5개 특성만 사용하여 장르, 아티스트 선호, 청취 시간대 등 실제 취향을 결정하는 다양한 요소를 반영하지 못한다.

개선 방향: 특성을 10개 이상으로 확장하고, 사용자 평점·청취 횟수 데이터를 결합하면 더 정밀한 군집화가 가능하다.

자기점검 체크리스트

  • ☑ 관심 분야가 명시되고, 기대 효과가 구체적으로 서술되어 있다.
  • ☑ 현재 모델의 한계가 언급되어 있다.
  • ☑ 성능 향상을 위한 개선사항이 제시되어 있다.

문항 8. 소감

달라진 생각, 어려웠던 점, 새롭게 알게 된 것, 또는 느낀 점을 자유롭게 서술하시오.

정답 레이블이 없는데도 AI가 스스로 비슷한 사람들을 묶는다는 개념이 처음엔 이해하기 어려웠는데, Scatter Plot에서 색깔로 군집이 분리되는 걸 보고 '아, 이게 군집화구나' 하고 직관적으로 이해됐다.

K=3에서 Silhouette Score가 가장 높았는데, 직접 결과를 보니 헬스 팬 / 공부 팬 / 파티 팬이라는 구분이 실생활 경험과 딱 맞아떨어져서 신기했다.

음악과 데이터에 모두 관심이 있어서, 나중에 실제 스트리밍 데이터로 더 정교한 취향 분석 모델을 만들어 친구들에게 맞춤 플레이리스트를 추천해주고 싶다.

자기점검 체크리스트

  • ☑ 기계학습 구현 과정에서 새롭게 알게 된 것이 포함되어 있다.
  • ☑ 자신의 경험을 바탕으로 진솔하게 작성되어 있다.
