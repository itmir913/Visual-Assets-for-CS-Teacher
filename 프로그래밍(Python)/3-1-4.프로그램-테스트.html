Chapter 3. 소프트웨어 개발

3-1-4. 프로그램 테스트

작성한 코드가 기획 의도대로, 설계 조건에 맞춰 완벽하게 돌아가는지 검증하고 수정합니다. 구현 후 바로 배포하면 안 되는 이유가 여기에 있습니다.

학습 목표 (Objective)

"내가 만든 프로그램에 버그가 없는지 어떻게 확인할 수 있을까?"

  • 소프트웨어 테스트의 종류(단위·통합·시스템)와 단계를 설명할 수 있다.
  • 오류 보고서를 작성하고 디버깅 방법을 이해할 수 있다.

Section 1

단계별 테스트의 종류

소프트웨어 테스트는 작은 단위에서 시작하여 전체 시스템으로 확장하며 꼼꼼하게 진행합니다.

단위 테스트

개별 함수나 모듈이 설계대로 작동하는지 최소 단위로 검사합니다.

구현 예시:
"중간고사 반영 수식"이 정확히 30%를 계산하는지 단일 수식만 확인.

통합 테스트

단위 모듈들을 합쳐서 데이터가 서로 잘 흐르는지 인터페이스를 검사합니다.

구현 예시:
입력받은 값이 계산 함수를 거쳐 출력 화면까지 잘 전달되는지 확인.

시스템 테스트

전체 시스템이 사용자의 요구사항(기획)을 만족하는지 최종 확인합니다.

구현 예시:
실제 학교 성적 산출 기준에 맞춰 소수점 자리수까지 정확한지 최종 점검.

Section 2

오류 보고서와 디버깅

테스트 중 발견된 예상 결과와 실제 결과의 차이를 기록하고, 원인을 찾아 수정(디버깅)합니다.

입력 데이터 예상 결과 실제 결과 상태
100, 100, 100 입력 100.0점 100.0점 PASS
숫자 대신 'A' 입력 오류 안내 출력 프로그램 강제 종료 FAIL

디버깅(Debug) 계획

문자 입력 시 발생하는 ValueError를 방지하기 위해, 구현 단계의 코드에 예외 처리(try-except) 구문을 추가하여 보완해야 합니다!

Section 3

왜 테스트를 해야 할까요?

  • 품질 보장: 기획했던 모든 기능이 정상적으로 작동하는지 확인합니다.
  • 신뢰성 확보: 사용자가 오류 없이 안심하고 프로그램을 사용할 수 있게 합니다.
  • 비용 절감: 배포 후 발견되는 큰 버그를 미리 방지하여 수정 비용을 줄입니다.

Section 4

축하합니다! 개발 완료!

기획부터 테스트까지, 여러분은 소프트웨어 개발의 모든 과정을 성공적으로 마쳤습니다.

이제 여러분의 프로그램을 세상에 내놓을 준비가 되었습니다.

학습 정리

테스트 3단계

  • • 단위 테스트: 개별 함수·모듈 최소 단위 검사
  • • 통합 테스트: 모듈 간 데이터 흐름 검사
  • • 시스템 테스트: 전체 요구사항 최종 확인

테스트의 가치

품질 보장 · 신뢰성 확보 · 비용 절감. 배포 전 테스트는 선택이 아닌 필수입니다.
