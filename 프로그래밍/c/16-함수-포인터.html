함수 포인터

지금까지 포인터가 가리킨 것은 자료였습니다.
그런데 함수도 메모리에 놓여 있습니다.

학습 목표

  1. 함수 이름이 함수가 놓인 자리를 뜻한다는 것을 설명할 수 있다.
  2. 함수 포인터를 선언하고 괄호가 왜 있어야 하는지 설명할 수 있다.
  3. 함수를 넘겨받아 동작이 달라지는 함수를 만들 수 있다.
  4. 함수 포인터 배열로 여럿 가운데 골라 쓸 수 있다.

함수에도 자리가 있다

메모리에 놓이는 것은 자료만이 아닙니다.

프로그램을 돌리면 변수만 메모리에 놓이는 것이 아닙니다. 「무엇을 하라」는 명령들도 메모리에 올라가야 컴퓨터가 하나씩 읽어 실행합니다. 함수는 그 명령들을 묶어 놓은 것이니 함수도 메모리 어딘가에 놓여 있고, 따라서 자리 번호를 가집니다.

배열 이름과 같은 이야기입니다

배열 이름은 첫 칸이 있는 자리를 뜻했습니다. 함수 이름도 그 함수가 놓인 자리를 뜻합니다. 그래서 &를 붙이지 않고 이름을 그대로 씁니다.

닮은 점이 하나 더 있습니다. 함수 이름도 변수가 아닙니다. twice = square;라고 쓸 수 없습니다 — 이름은 「거기 있다」를 뜻할 뿐 값을 담는 자리가 아니기 때문입니다. 담아 두고 바꿔 쓰려면 그것을 담을 변수가 따로 있어야 합니다.

fp(10)이 twice(10)과 똑같이 돕니다

fp에 담긴 것은 twice가 놓인 자리입니다. 그 자리를 괄호와 함께 쓰면 「거기 있는 명령들을 실행하라」가 됩니다. 그래서 결과가 같습니다.

fp == twice가 참인 것도 확인해 두세요. 담긴 번호가 같다는 뜻입니다. 포인터끼리 ==로 물으면 같은 곳을 가리키는지를 답한다는 규칙이 그대로 적용됩니다.

스스로 확인

fp = square;로 갈아 끼운 뒤 fp(10)을 부르면 무엇이 나올까요? twice는 그대로일까요?

모양 읽는 법

이 차시에서 가장 낯선 것은 문법의 생김새입니다.

int (*fp)(int);는 지금까지 본 선언과 모양이 다릅니다. 세 조각으로 끊어 읽으면 뜻이 보입니다.

조각 무엇을 정하나 읽는 말
(*fp) 이름과 포인터라는 것 fp는 가리키는 변수인데
(int) 가리킬 함수가 받는 것 정수 하나를 받아서
맨 앞 int 가리킬 함수가 돌려주는 것 정수를 돌려주는 함수를 가리킨다

가리킬 함수의 「모양」이 곧 자료형입니다

int *가 「정수를 가리킨다」였듯, 함수 포인터는 「이런 모양의 함수를 가리킨다」입니다. 모양을 이루는 것은 돌려주는 종류와 받는 것들입니다.

그러니 모양이 다르면 담을 수 없습니다. int (*fp)(int)에 정수 둘을 받는 함수를 담으려 하면 컴파일러가 붙잡습니다. 「몇 칸을 읽을지」가 자료형이었던 것처럼 여기서는 「어떻게 부를지」가 자료형입니다.

괄호를 빼면 아예 다른 것이 됩니다

int *fp(int);이라고 쓰면 「정수를 받아 정수의 자리를 돌려주는 «함수»」를 선언한 것이 됩니다. 변수가 아니라 함수입니다. 그래서 fp = twice;라고 담으려 하면 「담을 수 있는 자리가 아니다」라며 컴파일이 멈춥니다.

괄호는 *를 이름에 먼저 붙이라는 표시입니다. 괄호가 없으면 뒤의 ()가 먼저 붙어 「함수」로 읽히기 때문입니다. (*out)[i]에서 괄호를 씌운 것과 같은 까닭입니다.

부를 때는 fp(10)으로 씁니다

(*fp)(10)이라고 적은 코드도 볼 수 있습니다. 둘 다 됩니다. 「따라가서 부른다」는 뜻을 드러내려고 앞의 방식을 쓰기도 하는데, 이 강의노트에서는 짧은 쪽으로 통일합니다.

스스로 확인

실수 둘을 받아 실수를 돌려주는 함수를 가리키려면 어떻게 적어야 할까요? 세 조각을 하나씩 채워 보세요.

동작을 넘기기

함수 포인터를 왜 만드는지가 여기서 드러납니다.

지금까지 함수에 넘긴 것은 「무엇을」이었습니다 — 숫자, 배열, 자리 번호. 함수 포인터를 넘기면 「무엇을 할지」까지 넘길 수 있습니다.

같은 함수가 두 가지 일을 합니다

apply는 「배열을 하나씩 훑어 찍는다」는 뼈대만 갖고 있습니다. 각 칸에 무엇을 하는지는 정해 두지 않았습니다. 그것을 부르는 쪽이 넣어 줍니다.

함수 포인터가 없다면 apply_twice와 apply_square를 따로 만들어야 했을 것입니다. 훑는 부분은 글자 하나 다르지 않은데도 말입니다. 「같은 일이 여러 곳에」 있으면 묶는다던 함수의 요점이 한 겹 더 올라간 것입니다.

쓰는 쪽에서는 이름만 적습니다

apply(data, 5, twice)에서 twice 뒤에 괄호가 없는 것을 보세요. twice(…)라고 적으면 「지금 불러서 그 결과를 넘겨라」가 되고, twice라고만 적으면 「이 함수 자체를 넘겨라」가 됩니다. 괄호 하나가 「부르기」와 「가리키기」를 가릅니다.

스스로 확인

칸마다 값을 찍지 않고 바꿔 넣고 싶다면 apply를 어떻게 고쳐야 할까요? 배열은 이미 자리로 넘어와 있습니다.

골라 쓰기

담을 수 있으면 배열에도 담을 수 있습니다.

함수 포인터도 값을 담는 변수이니 배열로 여럿 늘어놓을 수 있습니다. 그러면 첨자 하나로 「어느 동작을 쓸지」를 고르게 됩니다.

int (*op[3])(int, int)을 끊어 읽습니다

가운데가 *op[3]이므로 op는 셋짜리 배열이고, 담는 것은 포인터이며, 가리킬 함수는 정수 둘을 받아 정수를 돌려줍니다. 안에서 밖으로 읽어 나가면 아무리 길어도 풀립니다.

op[i](a, b)는 i번째에 담긴 함수를 부르는 것입니다. if·switch로 갈래를 벌여 놓는 대신 첨자 하나로 고르는 것이라, 동작을 더할 때 배열에 한 줄만 보태면 됩니다.

첨자가 칸 밖으로 나가면 더 위험합니다

배열의 칸 밖을 짚으면 엉뚱한 값이 나온다고 했습니다. 함수 포인터 배열에서는 엉뚱한 값을 「실행」하려 듭니다. 고를 번호가 밖에서 들어온다면 범위를 먼저 확인해야 합니다.

필요할 때만 씁니다

함수 포인터는 코드를 읽는 사람에게서 「지금 무엇이 불리는지」를 감춥니다. op[i](a, b)라는 줄만 봐서는 더하는지 곱하는지 알 수 없습니다. 갈래가 두셋뿐이라면 if로 또박또박 적는 편이 읽기 쉽습니다.

값이 있는 자리는 「동작을 나중에 정해야 할 때」입니다 — 쓰는 사람이 고르게 하거나, 뼈대만 만들어 두고 세부를 나중에 끼워 넣을 때요. 포인터를 쓸 수 있다고 늘 쓰는 것이 낫지는 않다는 말이 여기에도 그대로 적용됩니다.

핵심 정리

함수 이름도 자리다

명령들도 메모리에 놓이므로 함수에도 주소가 있다. 배열 이름처럼 & 없이 그대로 쓰고, 배열 이름처럼 변수가 아니다.

모양이 자료형이다

돌려주는 종류와 받는 것들이 「어떤 함수를 가리킬 수 있는지」를 정한다. 모양이 다르면 담을 수 없다.

괄호가 뜻을 가른다

int (*fp)(int)는 변수, int *fp(int)는 함수다. 넘길 때도 twice는 가리키기, twice()는 부르기다.

동작을 나중에 정한다

뼈대는 한 번만 만들고 무엇을 할지는 부르는 쪽이 넣는다. 다만 읽는 사람에게서 「지금 무엇이 불리는지」를 감추므로 필요할 때만 쓴다.
