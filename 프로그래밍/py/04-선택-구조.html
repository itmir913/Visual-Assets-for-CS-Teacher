학습 목표

  1. 조건에 따라 실행할 줄을 갈라놓을 수 있고, 갈래가 셋 이상일 때 이어 붙일 수 있다.
  2. 들여쓰기가 어디까지를 묶는지 설명하고, 들여쓰기를 어겼을 때 무슨 일이 일어나는지 안다.
  3. 조건이 여럿일 때 겹쳐 쓰는 것과 논리 연산자로 묶는 것을 견주어 고를 수 있다.
  4. 값 하나를 고르는 한 줄 표현을 읽고 쓸 수 있다.

조건에 따라 갈라지기

지금까지의 프로그램은 언제 돌려도 같은 줄을 같은 순서로 지났습니다.

여기까지 만든 프로그램은 위에서 아래로 한 번 흐르고 끝났습니다. 입력이 무엇이든 지나가는 줄이 같았습니다. if는 여기에 갈림길을 놓습니다.

읽는 순서

  1. if 뒤의 조건을 계산한다 — 앞 차시에서 본 대로 결과는 참 아니면 거짓이다.
  2. 참이면 들여쓴 줄들을 실행하고 else 쪽은 건너뛴다.
  3. 거짓이면 else 쪽만 실행한다.

둘 중 하나만 실행됩니다. else는 없어도 됩니다 — 그러면 조건이 거짓일 때 아무 일도 하지 않고 지나갑니다.

콜론을 빠뜨리기 쉽습니다

조건 끝의 :는 「여기부터 딸린 줄들이 시작된다」는 표시입니다. 빠뜨리면 SyntaxError가 나는데, 오류 메시지가 다음 줄을 가리켜 엉뚱한 데를 보게 되기 쉽습니다. if를 썼는데 오류가 나면 줄 끝에 콜론이 있는지부터 보세요.

갈래가 셋 이상이면 elif로 이어 붙입니다. 「else if」를 줄인 낱말입니다.

위에서부터 보다가 «맞는 첫 곳»에서 멈춥니다

85점은 score >= 80도 참이고 score >= 70도 참입니다. 그런데 B만 찍힙니다. 한 갈래가 걸리면 나머지는 보지도 않기 때문입니다.

그래서 순서가 뜻을 바꿉니다. 조건을 뒤집어 score >= 70을 맨 위에 두면 95점도 C가 되어 버립니다. 좁은 조건부터 넓은 조건 순으로 놓아야 합니다.

윤년 판별은 갈래가 순서를 타는 좋은 예입니다. 4의 배수이면서 100의 배수가 아니면 윤년이고, 그 조건에서 걸러진 100의 배수 가운데 400의 배수만 다시 윤년입니다. 2024와 2000은 윤년이고, 1900은 아닙니다.

스스로 확인

위 등급 코드에 score가 105일 때는 무엇이 찍힐까요? 잘못된 값을 걸러 내려면 어디에 무엇을 더해야 할까요?

들여쓰기가 곧 문법입니다

파이썬에서는 빈칸이 눈속임이 아니라 뜻입니다.

if에 딸리는 줄이 어디까지인지는 들여쓰기가 정합니다. 묶어 주는 괄호 같은 것이 따로 없습니다.

들여쓴 만큼만 딸립니다

print("수고했습니다")는 들여쓰지 않았으므로 조건과 상관없이 실행됩니다. 40점이어도 찍힙니다. 이것은 오류가 아니라 시킨 대로 한 것입니다 — 「무엇을 안에 넣고 무엇을 밖에 둘지」를 빈칸으로 말하는 셈입니다.

반대로 아예 안 들여쓰면 «문법 오류»입니다

if 뒤에는 딸린 줄이 적어도 하나 있어야 합니다. 하나도 없으면 파이썬이 IndentationError로 그 자리에서 멈춥니다. 조용히 지나가지 않는다는 점에서 오히려 다행인 실수입니다.

빈칸 넷으로 통일합니다

몇 칸을 들여쓸지는 정해져 있지 않습니다. 같은 묶음 안에서 같기만 하면 됩니다. 그래도 빈칸 넷이 널리 쓰이는 약속이니 그대로 따르는 편이 좋습니다.

탭과 빈칸을 섞지 마세요. 화면에는 똑같이 보이는데 파이썬은 다르게 읽어, 눈으로는 절대 찾을 수 없는 오류가 됩니다. 편집기에서 「탭을 빈칸으로 바꾸기」를 켜 두면 이 문제 자체가 생기지 않습니다.

스스로 확인

if 안에서 아무것도 하지 않고 넘어가고 싶을 때는 어떻게 할까요? 빈 줄로 두면 오류가 나는데요.

조건이 여럿일 때

겹쳐 쓸 수도 있고 한 줄로 묶을 수도 있습니다.

if 안에 if를 또 둘 수 있습니다. 중첩이라고 합니다. 한 겹 들어갈 때마다 네 칸씩 더 들여씁니다.

같은 판정을 겹치지 않고 쓸 수도 있습니다.

둘은 같지 않습니다

합격을 가려내는 것만 보면 결과가 같지만, 안 되는 경우를 갈라 주는 방식이 다릅니다. 겹쳐 쓰면 「출석이 모자란 것」과 「점수가 모자란 것」을 따로 안내할 수 있고, 한 줄로 묶으면 둘이 한 덩어리가 되어 이유를 나눌 수 없습니다.

이유를 나눌 필요가 없으면 묶는 편이 읽기 쉽습니다. 겹침이 깊어질수록 오른쪽으로 밀려 두 겹까지가 읽기 좋은 한계입니다.

스스로 확인

출석이 모자랄 때와 점수가 모자랄 때 다른 말을 해 주고 싶다면, 두 방식 가운데 어느 쪽을 골라야 할까요?

참으로 보는 것과 거짓으로 보는 것

조건 자리에 꼭 견주기만 오는 것은 아닙니다.

if 뒤에는 참·거짓이 아닌 값도 놓을 수 있습니다. 그러면 파이썬이 그 값을 참 쪽인지 거짓 쪽인지 판정해 줍니다.

거짓으로 보는 것 참으로 보는 것
0, 0.0 0이 아닌 모든 수 — 음수도 참이다
"" 빈 글자 글자가 하나라도 있으면 참 — "0"도 참이다
False True

"0"은 참입니다

따옴표가 붙은 순간 「글자 하나가 들어 있는 것」이 되기 때문입니다. input으로 받은 값은 언제나 글자이므로, 「0을 입력했는지」를 보려면 수로 바꿔서 견주어야 합니다.

고르는 것이 실행할 줄이 아니라 값 하나일 때는 한 줄로 쓸 수 있습니다.

「참일 때 값 — 조건 — 거짓일 때 값」 차례로 읽습니다. 짧아서 좋지만 겹쳐 쓰면 금세 읽기 어려워지므로, 그럴 때는 if로 풀어 씁니다.

스스로 확인

if score:라고 쓰면 0점인 학생은 어느 쪽으로 갈까요? 이것이 왜 위험한 조건일까요?

핵심 정리

if · elif · else

위에서부터 보다가 맞는 첫 갈래에서 멈춘다. 그래서 순서가 뜻을 바꾼다 — 좁은 조건을 위에 놓는다. 줄 끝의 콜론을 빠뜨리지 않는다.

들여쓰기가 문법

들여쓴 만큼만 조건에 딸린다. 하나도 안 들여쓰면 IndentationError다. 빈칸 넷으로 맞추고 탭과 섞지 않는다.

겹치기와 묶기

겹쳐 쓰면 안 되는 이유를 나눌 수 있고, and로 묶으면 한 덩어리가 된다. 이유를 나눌 필요가 없으면 묶는 편이 읽기 쉽다.

참으로 보는 값

0과 빈 글자가 거짓, 나머지는 참이다. "0"은 참이므로 입력값을 볼 때는 수로 바꿔서 견준다.

퀴즈

1. score가 95일 때, 조건을 score >= 70 → score >= 80 → score >= 90 순으로 elif를 늘어놓으면?

2. if 다음 줄을 들여쓰지 않으면?

3. 다음 중 조건 자리에서 거짓으로 보는 것은?
